## 0. Decisions

### 0.1 Product rules this contract enforces (not negotiable, and every section below is checked against them)

1. **HOLDS means "no counterexample under this evidence, this coverage and this freshness". It never means "secure".**
   No field, wording template, name or output of any P3 component may phrase it otherwise.
2. **UNKNOWN never becomes HOLDS.** A result that cannot be produced, proven or published is absent or UNKNOWN, never HOLDS.
3. **Violations win.** A disclosed VIOLATED rejects by default, whether or not the consumer required that invariant.
4. **The attestation vocabulary is fixed.** The statement carries enums, ids, hashes, integers and timestamps and
   **no free text**. Every human sentence is generated by the verifier from a table the spec owns.
5. **Privacy by default.** No hostname, IP address, node reference, witness, label value or tenant UUID appears in a
   signed statement or in any public file. Merkle commitments are blinded with a per-estate secret.
6. **Fail safe.** Any failure while issuing means "do not issue" (the previous statement then lapses at its own
   `valid_until`); any failure while verifying means "not accepted" (exit 1 or 2), never exit 0.

### 0.3 How the three scouting designs were reconciled

| Topic | Scout A (statement) | Scout B (server side) | Scout C (spec and verifier) | Resolution here |
|---|---|---|---|---|
| Source of verdicts | fresh single-snapshot evaluation | stored `last_result` + settle window | stored results | **A** (D1): only a fresh evaluation has a graph and the full blind-spot list to commit to; stored rows are a trigger and a cross-check |
| Unit of issuance | one chain per estate, many subjects | one chain per (tenant, domain) | exactly one `domain:` subject | **per publication** (D2): one chain, one subject, one disclosure profile; an IP-only estate gets a `paddock-estate:` subject |
| Key id | 64 hex | 32 hex | 32 hex | **32 hex**, the first half of sha256(raw public key) (D6); the repo's agent envelope already uses this form; the full hash is `fp` |
| Canonical JSON | ASCII subset, `\"` and `\\` allowed | same subset | stricter: no escape sequences, unsigned ints only | **C** (D4): strings may not contain `"` or `\`, so a conforming document has no escape sequence at all |
| base64 | standard or URL-safe | URL-safe in places | standard, padded, canonical | **C** (D5) |
| Predicate extensibility | strict, unknown keys invalid | n/a | unknown non-critical keys ignored + `critical` list | **A** (D8): strict; new fields mean a new `predicateType` |
| Coverage ratios | permille | n/a | basis points | **basis points** (`required_bp`) |
| Anchor | optional field, Ed25519 | additive detached `sigs[]` (proved legacy anchors break otherwise) | rewrite as v2 with `tenant_id` | **B** for the mechanism, with the random `estate` id instead of the tenant UUID or a hash of it (D15) |
| Key hierarchy | cert binds kid to estate | root -> issuer -> tenant, separate revoker | root -> issuer -> tenant | **B and C agree** (D16) |
| Revocation signers | min_seq supersession in `revoked.json` | revoker or sibling tenant key | issuer | revoker or issuer only; `superseded[]` carries min_seq (D20) |
| Anchor required to publish | optional | required by default | optional | **optional** by default, `PADDOCK_ATTEST_REQUIRE_ANCHOR` per deployment, consumer policy `anchor: required` (D15) |
| Policy tree | blinded, all declared invariants | n/a | unsalted over disclosed results, recompute when `disclosed == total` | **A**: blinded over ALL declared invariants; the verifier does not recompute it (it cannot know the nonces); counts are the public check |
| Default disclosure rule in the verifier | counts shown, never a reject by itself | n/a | `disclosure: all` rejects partial | **A for the baseline**, C's rule as the policy option `disclosure: complete` (D9) |
| Where DNS is resolved | n/a | dnspython on the server | stdlib DoH/UDP/file in the verifier | both: the server uses dnspython (already used by `scope_proof`), the verifier is stdlib-only |
| P-256 / BYOK | n/a | per-key `alg`, BYOK defaults to P-256 | Ed25519 only in v1 | **Ed25519 only in spec v1**; `alg` is a per-key field and `max_message_bytes` is part of the backend contract; P-256 and BYOK are reserved (D7, D18) |

### 0.4 Engineering decisions (each with its reason)

| # | Decision | Why |
|---|---|---|
| D1 | **Verdicts come from a fresh single-snapshot evaluation made at issuance**, on the same graph document that is Merkle-committed, in one read-only transaction, with `now` = the DB clock floored to the second. `invariants.last_result` is used only (a) as the trigger "something changed, re-evaluate" and (b) as a determinism cross-check (same `doc_sha` must give the same verdict class, otherwise the result is withheld). It is never the source and never upgrades a fresh result. | The engine stores no graph, caps stored blind spots at 200 (`MAX_STORED_BLIND_SPOTS`), writes runs only on transitions, and evaluates invariants at different graph times. None of those can back an exact graph or blind-spot commitment, and mixing times allows cherry-picking across time. No library or runner change is needed. |
| D2 | **The unit of issuance is a publication** `(estate, subject)`: its own `seq`/`prev` chain, its own disclosure profile, exactly one subject (`dns:<domain>` or `paddock-estate:<id>`). One evaluation pass per estate feeds every due publication. At most 1 estate publication and 10 domain publications per estate. | A statement naming several domains would link them to every reader of any one bundle. One chain per audience makes `seq`/`disclosed` meaningful. Residual linkage through the shared key fingerprint is accepted and disclosed (D31). |
| D3 | The in-toto **subject digest is `sha256(UTF-8(subject name))`**; the authorisation set is carried in `predicate.scope` (a digest, counts, never the entries). | The verifier can recompute the subject digest from the name alone. The scope digest binds the statement to a declared, proven authorisation set that the owner can later disclose as `scope.json`. |
| D4 | **Signed JSON uses one strict byte profile, PCJ** (section 2.1): ASCII only, no string escapes, unsigned integers up to 2^53-1, booleans, no null and no floats, keys sorted by byte value, no whitespace. The verifier re-encodes the parsed value and requires byte equality with the received bytes. | The repo today mixes `ensure_ascii` True (audit, anchors) and False (licensing). One profile removes Unicode, escape, float-format and key-order disagreements between implementations, and any RFC 8785 library produces identical bytes for conforming input. |
| D5 | **base64 is the standard alphabet with padding, canonical** (re-encode and compare), for payloads, signatures and public keys. Digests and ids are lowercase hex. | Python's `b64decode` silently drops invalid characters and accepts non-zero trailing bits; `atob` and Node `Buffer` are lenient too. Strictness costs nothing because producers are ours. Deliberately narrower than DSSE's "accept both". |
| D6 | **DSSE envelope, `payloadType` `application/vnd.in-toto+json`, exactly one Ed25519 signature**, `keyid` = `kid` = first 32 hex of sha256(raw 32-byte public key). The statement repeats it as `predicate.kid` (signed). The verifier never trusts a key carried in the envelope. | Standard shape and tooling; one signature avoids threshold ambiguity (multi-signature needs a `predicateType` v2); a signed `kid` stops re-signing under another key of the same estate. |
| D7 | **Spec v1 defines Ed25519 only.** Every implementation applies its own pre-checks (S < L, reject small-order and non-canonical public keys) before calling a library. The algorithm of a key comes from its cert, never from the envelope; an unknown `alg` is UNVERIFIABLE (exit 2), never a fallback. | Probe: OpenSSL (`cryptography`) accepts the identity public key with an identity signature over any message. WebCrypto engines differ on S >= L. A code-level pre-check makes results engine-independent. |
| D8 | **The predicate is strict**: an unknown key anywhere is INVALID. New fields or semantics mean a new `predicateType` (`.../containment/v2`), which a v1 verifier reports as UNVERIFIABLE (exit 2). There is no `critical` list and no extension map. | An extension map is a free-text channel; silently ignoring an unknown field is how meaning gets weakened. Verifier upgrades are cheap compared to a misread attestation. |
| D9 | **Disclosure defaults to `holds_only` and std invariants only.** `disclosure.verdicts = all` (VIOLATED and UNKNOWN as counts and enum codes, never witnesses) and `disclosure.custom = true` are explicit owner settings per publication. Withholding is visible through counts (`total`, `enabled_std`, `enabled_custom`, `disclosed`, `versions`); in `all` mode the counts are self-checking. A consumer policy can require `disclosure: complete`. The baseline policy does not reject partial disclosure, but always prints the counts and the missing std ids. | Private-by-default (O3) and HOLDS-only are the owner's rules. Rejecting every default publication under the baseline would make the default product fail its own verifier. The honest consequence (a reader of a `holds_only` statement cannot tell violated from withheld) is stated in the limits text and in section 12. |
| D10 | **Commitments**: three RFC 6962/9162 Merkle trees over blinded, domain-separated PCJ leaves: one **graph tree** (nodes with labels, edges, coverage facts, fact meaning digests), one **policy tree** over ALL declared invariants (enabled or not), one **blind-spot tree per result**. Leaf nonce = HMAC-SHA256 under a per-estate random `commit_key`; leaves are sorted by leaf hash (a set commitment). | Labels (`app-tier` boundaries, zones) are verdict inputs and MVP 10a requires committing the boundary set, so edges alone are not enough. Blinding stops guessing low-entropy leaves (IPs, ports) from a root. Deterministic nonces keep roots stable across refreshes when nothing changed. |
| D11 | **Tier rules**: `tier` is copied from `Result.evidence_tier` (the weakest relied-on fact); a published HOLDS needs `tier >= max(min_tier, configured)`; `tier <= cap(assertion)` with cap `configured` for `host-config` and `observed` otherwise; `tested` is capped out (setting `ATTEST_MAX_TIER`, default `observed`) until P5 ships and the spec grows a probe-evidence profile; `declared` is never public. The issuer, its self-verification and the verifier each re-assert this. | "An attestation can never claim a tier the evidence did not reach." A `declared` HOLDS is only the tenant's say-so. |
| D12 | **Coverage is published as integers**: the verdict-relevant pair (`universe`, `covered`, the P1.5 D8 basis), the tenant-wide pair, and `required_bp` (floor of the engine's float, so the statement never claims a stricter floor than the one applied). The verifier compares with integer cross-multiplication and displays a floored percentage. | Floats make cross-language equality and rounding up past a threshold possible. |
| D13 | **Time**: `issued_at` is the DB clock; default validity 24 h (tenant range 1 to 72 h, spec hard cap 7 days); per-result `valid_until` is the engine's; the statement `valid_until` is only the issuance cap. Refresh at `ttl/4`; a downgrade issues within one 60 s tick; an upgrade is debounced 300 s; no issuance if the horizon is under 15 minutes. | Bounds the offline replay window to a day by default; narrows the real exposure on a flip to about a minute for an honest issuer; a flapping evaluator cannot advertise brief HOLDS. |
| D14 | **Chain**: `seq` strictly +1 per publication, `prev` = sha256 of the exact payload bytes of seq-1 (absent at seq 1), `UNIQUE (tenant, publication, seq)`, **the seq is allocated and the signature made inside one DB transaction** so a sign failure leaves no gap. After a restore the publisher continues from max(local, remote) + 1; if the remote is unreachable it refuses to issue. The chain continues across key rotation. | A gap then always means withholding. Hashing payload bytes is independent of signature and base64 variants. |
| D15 | **Anchor**: an additive detached `Anchor.sigs[]` list excluded from `signed_body()` (adding any dataclass field would change `asdict()` and so the HMAC-signed bytes of every stored legacy anchor, which Object-Lock objects cannot repair); Ed25519 over `b"paddock-anchor/v2\n" + PCJ(public anchor doc)`; the public doc names the random `estate` id, not the tenant UUID; anchor keys are a separate `usage = anchor` hosted key even for later BYOK tenants; signing is best effort (a missing key or backend yields a legacy-only anchor, never a blocked anchor); no silent downgrade (env flag + sticky state). The statement carries `audit_anchor` only when a v2-signed anchor exists. | Keeps old binaries, old anchors and all three sinks working. Anchoring is a core integrity control and must not depend on attestation infrastructure or a customer KMS. The honest outsider-visible claim is in section 3.7. |
| D16 | **Key hierarchy**: offline attestation **root** (a new key, never the license key) -> online **issuer** (`issue-cert`, 1 y) and online **revoker** (`revoke`, 1 y, deny-only) -> per-estate **attest** and **anchor** keys. Certificates are DSSE-wrapped PCJ JSON, not X.509. Chain length is fixed at 2 below the root; a self-hoster may pin its own issuer as a root. | An offline root cannot sign a cert for every tenant renewal or a revocation list every day. The license key signs un-domain-separated JSON and is exercised on every license issue, so reusing it invites cross-protocol confusion. No ASN.1 parser in the open verifier. |
| D17 | **Key storage**: dedicated `PADDOCK_ATTEST_KEK` (+ `..._PREVIOUS`), HKDF per (tenant, kind, kid), AES-256-GCM with AAD binding tenant, kind, kid, usage and alg, sealed seeds in their own table `attest_key_secrets` (deleting the row is the crypto-erase), the per-estate `commit_key` sealed the same way, no ephemeral dev key (creation is refused without a KEK), no unsealed-key cache, sign-then-verify. Only `attest/backend_local.py` and `attest/crypto.py` may touch that table (a lint test enforces it). | Independent blast radius and rotation from integration secrets; AAD stops row, tenant and usage swaps; an ephemeral key would publish keys that vanish on restart. |
| D18 | **`KeyBackend` interface** (generate, sign, destroy, health) with `alg`, `custody` and `max_message_bytes` as part of the contract; no export surface. Ships now: `LocalAesGcmBackend` (hosted). `AwsKmsBackend` is a stub behind `PADDOCK_ATTEST_BYOK_ENABLED=false`; no BYOK route exists in P3. | BYOK is a decision the owner took for later. Raw-message KMS limits (AWS: 4096 bytes, to be verified; a nine-invariant statement is about 5 KB) mean a BYOK backend needs P-256/digest signing, which is a spec 1.1 item with its own vectors. |
| D19 | **DNS binding**: TXT at `_paddock-attest.<exact domain>`: `v=1; kid=<32hex>; fp=sha256:<64hex>[; keys=https://...]`. `kid` MUST be the first 32 hex of `fp`; at most 3 records are published and 8 parsed; a duplicate tag is malformed; an unknown `v` is ignored; 450 bytes is a hard generation cap. The verifier resolves with its own stdlib resolvers (DoH, UDP, system, file) and requires all answering resolvers to agree; DNSSEC is **reported, not required** (`require_dnssec` is a consumer policy). | Matches MVP 7.4; sizes measured at 117 to 237 bytes; most corporate zones are unsigned so requiring DNSSEC would block most customers, but the report must say honestly that AD is the resolver's claim. |
| D20 | **Revocation**: one signed `revoked.json` per estate (revoker or issuer key), re-signed at least daily, stale after `next_update + 48 h` (stale means exit 2, never accept). `compromise` rejects every statement of that key regardless of its claimed `issued_at`; `superseded` and `cessation` reject statements with `issued_at >= revoked_at`. A `superseded[]` list (`subject`, `min_seq`) is signed on every downgrade flip so an online verifier rejects the older "HOLDS" statement. | A claimed `issued_at` is attacker-controlled once a key is compromised. Freshness stops an attacker who controls the host from freezing an old list. The supersession closes the "stale HOLDS stays valid until valid_until" window for any verifier that fetches the list (an offline copy is bounded by `valid_until`; stated in section 12). |
| D21 | **Self-verification**: before storing or serving any envelope the issuer runs the **same open verifier code** (`paddock_verify`, imported by the orchestrator) over its own envelope with the real key set; failure rolls back, raises an alert metric and sets an ack-required hold. Independent vectors (D26) catch common-mode bugs. | Catches signing, canonicalisation and wrong-key bugs before they are public; AGPL code may depend on an Apache package. |
| D22 | **Publishing** serves pre-rendered, publication-scoped objects from one table through a narrow exact-match RLS lookup policy (the `trust_links` pattern); public routes never read live tenant tables; every non-served case (unknown, malformed, unpublished, failing, foreign) returns the same 404. `serving` is a materialised flag recomputed by a 5-minute sweep from scope proof, DNS binding, key status, suspension and license. Push targets: hosted, file, S3. | A bug in a public handler then cannot leak a statement that was not rendered public, and nothing can be enumerated. |
| D23 | **API / RBAC / licensing**: new router modules only; private reads use the default `read`, every mutation falls through to the deny-closed `admin`; two explicit `auth.py` rules (public GET/HEAD for the bundle, `admin` for disclosure-material reads); two new `FEATURES` entries (`attestations_public`, `attestation_byok`, both enterprise); private issuing and preview use the existing `assurance` flag; consequential mutations require a `justification` (min 8 chars) that lands in the audit row. | Minimises merge conflicts with P2.1, keeps the deny-closed default. |
| D24 | **Wording and limits are verifier-owned**: `wording-v1.json` (templates), `std-registry.json` (names per ruleset), `limits-v1.txt` (fixed text whose sha256 is in every statement). The conformance suite greps all output for a forbidden vocabulary. | Product rule 1 and 4: nobody, including an issuer or a custom invariant id, can phrase HOLDS as SECURE. |
| D25 | **The verifier** is a Python package (`verifier/paddock_verify/`) whose only runtime dependency is `cryptography`, with a fixed 11-step check order, stable reason codes, exit codes 0/1/2 (+64 usage), a JSON acceptance policy as the normative form and a strict YAML subset as sugar. | Matches MVP 8.3/8.4. |
| D26 | **Vectors come from an independent third implementation** (`tools/gen_vectors.py` + `tools/gen_cases.py`, stdlib + `cryptography`, importing neither the verifier nor the orchestrator). The verifier and the orchestrator producer each run against the committed corpus; CI runs the generator with `--check`. A language-neutral conformance runner drives any CLI. | If the generator shared code with the producer, a producer bug would be baked into the vectors. |
| D27 | **Engine and ruleset are published** (`engine.version`, `engine.ruleset` = digest over the shipped std digests). The spec ships `std-registry.json` (per ruleset: std id, digest, assertion kind, name) and `advisories.json` (engine versions with known false-HOLDS defects). An unknown ruleset is UNVERIFIABLE; a listed advisory rejects by default. | P1 review found three false-HOLDS defects; verifiers need an off-switch. Unknown must not mean accept. |
| D28 | **Anti-vacuity signals without a library change**: the issuer publishes selector sizes (`selected.from/to/stop_at`) computed with the public `ReachGraph.select`, plus `min_tier` and `max_age_s`. ## 1. Statement and predicate (exact)

### 1.1 Envelope

DSSE envelope, plain JSON (not required to be canonical, at most 512 KiB):

```json
{"payloadType":"application/vnd.in-toto+json","payload":"<base64 of PAYLOAD BYTES>","signatures":[{"keyid":"<32 hex kid>","sig":"<base64 of 64 bytes>"}]}
```

* Exactly the three top-level keys; `signatures` has exactly one entry with exactly the keys `keyid` and `sig`.
  Zero or two or more signatures is `sig.count_invalid`.
* **PAYLOAD BYTES** are the PCJ encoding (section 2.1) of the Statement. The verifier base64-decodes (strict, section
  2.2), parses strictly, re-encodes and requires byte equality (`schema.payload_not_canonical` otherwise).
* The signature input is the DSSE PAE (section 2.4) over `payloadType` and the **decoded** payload bytes. Ed25519,
  pure (no prehash).
* All hashes (`prev`, `anchor.digest`, proofs) are over decoded payload bytes, so base64 and envelope variants never
  influence them.

### 1.2 Statement

```json
{"_type":"https://in-toto.io/Statement/v1",
 "subject":[{"name":"dns:example.com","digest":{"sha256":"<sha256 hex of the UTF-8 bytes of the name>"}}],
 "predicateType":"https://paddock.dev/attestation/containment/v1",
 "predicate":{ ... }}
```

* `_type` and `predicateType` MUST equal these strings. An unknown `predicateType` is `predicate.unsupported_version`
  (UNVERIFIABLE) and nothing else of the statement is interpreted beyond steps 0 to 3.
* `subject` has **exactly one** entry. `name` is `dns:<domain>` (lowercase, A-label, no trailing dot, labels of at
  most 63 and a total of at most 253 characters, at least two labels, no IP literal) or `paddock-estate:<estate id>`.
  `digest` has exactly the key `sha256`.

### 1.3 Predicate

Types used below. **T** = `YYYY-MM-DDTHH:MM:SSZ` (regex, then calendar validation: no `:60`, no Feb 30, year
2000 to 9999). **H** = `sha256:` + 64 lowercase hex. **KID** = 32 lowercase hex. **ESTATE** = `e_` + 26 characters
of `[a-z2-7]`. **INV** = `[a-z][a-z0-9]{0,31}:[a-z0-9][a-z0-9-]{0,63}` (the engine's own `ID_RE`). **UINT** = integer
0 to 2^53-1. Optional fields are **omitted**, never null.

| Field | Type / rule |
|---|---|
| `estate` | ESTATE. Random 128-bit chain identity per tenant, stored once, **not derived from the tenant UUID**. Equals the cert's `estate`, and the `paddock-estate` subject when that is the subject. |
| `seq` | UINT >= 1, strictly +1 per publication. |
| `prev` | H = sha256 of the exact payload bytes of seq-1. Present **iff** `seq > 1`. |
| `issued_at` | T. DB clock, whole seconds. |
| `valid_until` | T. `issued_at < valid_until <= issued_at + 7 days`. |
| `kid` | KID. Equals the envelope `keyid`. |
| `snapshot` | `{"at": T, "graph": {"root": H, "size": UINT}}`. `snapshot.at <= issued_at <= snapshot.at + 900 s`. All results share this one time. |
| `scope` | `{"digest": H, "entries": UINT, "unproven": UINT, "private": UINT}`, section 5.6. |
| `policy` | `{"commitment": H, "total": UINT, "enabled_std": UINT, "enabled_custom": UINT, "disclosed": UINT, "versions": UINT}`. |
| `disclosure` | `{"verdicts": "holds_only"\|"all", "custom": bool}`. |
| `results` | array of **result** (below), sorted by `invariant` (byte order), unique, at most 256. |
| `engine` | `{"name": "paddock-assurance", "version": <semver-ish string [0-9A-Za-z.+-]{1,32}>, "ruleset": H}`. |
| `audit_anchor` | OPTIONAL `{"max_id": UINT, "head": 64 lowercase hex, "hash_alg": "sha256"\|"hmac-sha256", "at": T, "kid": KID, "digest": H}`, section 3.7. Present only when a v2-signed anchor exists. |
| `limits` | `{"id": "paddock-limits/1", "digest": H}`. **Mandatory.** `digest` is sha256 of the exact bytes of `limits-v1.txt` (section 13.2). |

Counting rules (checked by the verifier, section 8.3 step 1): `disclosed == len(results)`;
`disclosed <= enabled_std + enabled_custom <= total`.

**result** (all variants):

| Field | Type / rule |
|---|---|
| `invariant` | INV. A `std:` id MUST come from the registry of the statement's ruleset. |
| `digest` | H. The engine's invariant digest, an **opaque id** to the verifier (the legacy encoding behind it is frozen and is not PCJ; see 2.7). For a `std:` id it MUST equal the registry digest of the statement's ruleset. |
| `assertion` | `"unreachable"` `"exposes-only"` `"covered"` `"host-config"` (closed). |
| `verdict` | `"HOLDS"` `"VIOLATED"` `"UNKNOWN"` (closed). **`EXPIRED` is never issued**; it is derived by the verifier (section 8.5). Any other value is `schema.enum_unknown`. |
| `min_tier` | `"declared"` `"configured"` `"observed"` `"tested"`. The invariant's `evidence.min_tier`. |
| `max_age_s` | UINT. The invariant's `evidence.max_age` in seconds. |
| `coverage` | `{"universe": UINT, "covered": UINT, "required_bp": UINT <= 10000, "estate_universe": UINT, "estate_covered": UINT}`. `universe`/`covered` are `Result.relevant_universe`/`relevant_covered`; `estate_*` are `coverage_universe`/`coverage_covered`; `required_bp = floor(Decimal(repr(plan.coverage_required)) * 10000)`. `covered <= universe`, `estate_covered <= estate_universe`. |
| `blind_spots` | `{"root": H, "size": UINT, "truncated": bool}`. Root over the full in-memory `Result.blind_spots`; `truncated` is true iff the engine's own cap (`MAX_HOST_BLIND_SPOTS`, `MAX_ZONE_BLIND_SPOTS`) was hit. An empty list has the empty-tree root (`sha256:e3b0c442...b855`). |
| `selected` | `{"from"?: UINT, "to": UINT, "stop_at"?: UINT}`. Sizes of the invariant's selectors (`from_`, `to`, `via.stop_at`) from the public `ReachGraph.select`; for `host-config` only `to` = `Result.hosts["selected"]`. |
| `exceptions` | UINT = `len(Result.exceptions_used)`: declared allow-entries the verdict relied on. Reasons and targets stay private. |

Verdict-specific, **exactly** these and no others:

* `HOLDS`: `tier` (`"configured"` `"observed"` `"tested"`; **never `declared`**) and `valid_until` (T, the engine's
  `Result.valid_until` floored to the second, `> issued_at`). Both required.
* `VIOLATED`: `violations` (UINT >= 1, `Result.violation_count`). No witness, no node refs, ever.
* `UNKNOWN`: `reason_codes` (non-empty, sorted, unique array of the enum below).

`reason_codes` enum and the mapping from engine reasons (by the part before the first `:`; parameters are dropped):

| Engine reason (prefix) | Public code |
|---|---|
| `coverage_below_required` | `coverage_below_required` |
| `possible_via_unknown_edges` | `possible_via_unknown_edges` |
| `possible_via_zone_unknown`, `zone_unknown` | `zone_unknown` |
| `overlapping_selectors_too_large` | `selection_too_large` |
| `hosts_unknown`, `no_agent`, `agent_revoked`, host fact reasons | `host_evidence_unusable` |
| stale or missing evidence reasons | `stale_or_missing_evidence` |
| `empty_selector` | `empty_selector` |
| `graph_incomplete:*`, `graph_unavailable` | `graph_incomplete` |
| `invalid_definition` | `invalid_definition` |
| `evaluation_error` | `evaluation_error` |
| anything else | `other` |

A test enumerates every reason string the library can emit and requires it to map or be explicitly `other`.

**Deliberately absent**: ratios and percentages, titles, descriptions, reasons text, severity, node refs, IPs,
hostnames, witnesses, `graph_version` (leaks activity), per-result evaluated times, the tenant UUID, any "overall",
"score", "secure" or "pass" field, any statement-level tier. A statement-level tier is a verifier output (minimum over
disclosed HOLDS tiers).

### 1.4 Size limits

Payload at most 256 KiB; envelope at most 512 KiB; JSON depth at most 8 in the statement (16 for any other file);
results at most 256; any string at most 512 bytes. The hosted backend has no message cap; a backend with
`max_message_bytes` smaller than the PAE refuses with `statement_too_large_for_backend` and the issuer never truncates.

## 2. Canonicalisation, Merkle trees, DSSE PAE

### 2.1 PCJ: the signed JSON profile (a strict subset of RFC 8785)

Applies to statements, key certs, revocation lists, public anchor docs, Merkle leaf records and the scope document.

* The document is bytes that are pure ASCII `0x20` to `0x7E`. A BOM, any byte >= 0x80, any control byte (including a
  trailing newline) is rejected.
* Value types: object, array, string, **non-negative integer**, boolean. No null, no float, no exponent, no fraction.
* Integers: base 10, `0` or `[1-9][0-9]*`, at most 2^53-1. `-0`, `+1`, `01`, `1.0`, `1e2` are rejected.
* Strings: characters `0x20`-`0x7E` **except `"` and `\`**. Therefore a conforming document contains no escape
  sequence; any `\` is non-canonical. Object keys follow the same rule, are non-empty and unique.
* Objects: keys sorted by byte value (for ASCII identical to the UTF-16 code-unit order RFC 8785 requires). No
  insignificant whitespace.
* Limits: depth at most 16, total at most 1 MiB, enforced **before** parsing (length) and during it (depth).
* Encoder rule: write the value as above. Nothing else is needed, and any RFC 8785 implementation yields the same
  bytes for a conforming value. Python: `json.dumps(v, sort_keys=True, separators=(",", ":"),
  ensure_ascii=False, allow_nan=False)` equals PCJ for conforming values, and the producer MUST assert the charset
  first.
* Strict parse + canonical round trip: `loads(data)` rejects duplicate keys, NaN/Infinity, floats, null, depth over the
  limit, an integer over 2^53-1 (Python 3.11+ raises `ValueError` for an integer over 4300 digits: map it to the same
  error), trailing bytes and invalid UTF-8; then `dumps(loads(data)) == data` is required. Catch order matters:
  `CanonError` (a `ValueError` subclass) must be caught before `ValueError`, or it is relabelled.

Edge table the vectors MUST cover: `-0`, `1.0`, `1e2`, `1E2`, `NaN`, `Infinity`, `null`, `2^53`, a 5000-digit integer,
`"é"`, lone surrogate escape, `"A"`, `"\/"`, `"\n"`, BOM, leading and trailing whitespace, trailing newline,
duplicate keys at depth 1 and 5, unsorted keys, empty key, depth 17, 1 MiB + 1 bytes, `[1,2,]`, `01`, empty input,
trailing garbage, `true` as a number (`seq: true`).

### 2.2 base64

Standard alphabet, padding required, no whitespace, no line breaks, and `b64encode(b64decode(x)) == x` (rejects
non-zero trailing bits). The URL-safe alphabet and missing padding are rejected (`schema.base64_invalid`).

### 2.3 Merkle trees (RFC 6962 shape, RFC 9162 proofs)

* **Leaf record** = a PCJ object that always contains `"tree": "graph"|"policy"|"blind"` (cross-tree domain
  separation) plus the record fields. `leaf_json = PCJ(record)`.
* **Nonce** (32 bytes) = `HMAC-SHA256(commit_key, b"paddock/leaf-nonce/v1\x00" || SHA256(leaf_json))`. `commit_key`
  is a per-estate random 32-byte secret sealed like a signing seed (D17); it is **not** the signing key, so an HSM or
  KMS never has to compute HMACs.
* `leaf_hash = SHA256(0x00 || nonce || leaf_json)`; `node_hash = SHA256(0x01 || left || right)`; the tree shape is
  RFC 6962 `MTH` (split at the largest power of two strictly below n); the empty tree root is `SHA256("")`
  (`e3b0c442...b855`). No odd-node duplication. Roots are written `sha256:<hex>`.
* **Leaves are sorted by `leaf_hash`** (a set commitment, independent of input order); identical leaves are collapsed
  to one; `size` is the number of distinct leaves.
* **Inclusion proof** file (`proofs/<seq>/<tree>.json`, or `proofs/<seq>/blind__<invariant with ':' as '__'>.json` for a
  blind-spot tree; never served publicly, section 6.6):
  `{"v":1,"tree":"policy","size":3,"index":0,"nonce":"<hex>","record":{...fields without "tree"...},"path":["<hex>",...]}`.
  The verifier rebuilds `leaf_json = PCJ({"tree": <tree>, **record})`, computes `leaf_hash`, and walks `path` with the
  RFC 9162 section 2.1.3.2 algorithm:

```
verify(leaf_hash, index, size, path, root):
    if index >= size: fail
    fn, sn, r = index, size - 1, leaf_hash
    for p in path:
        if sn == 0: fail
        if fn & 1 or fn == sn:
            r = H(0x01 || p || r)
            if not fn & 1:
                while not fn & 1 and fn != 0: fn >>= 1; sn >>= 1
        else:
            r = H(0x01 || r || p)
        fn >>= 1; sn >>= 1
    return sn == 0 and r == root
```

  Never per-hop left/right flags. Pins: `leaf("")`-style vectors, empty root, sizes 0 to 17, every index of sizes 1, 2,
  3, 5, 7, 8, 9, 17, wrong index, wrong size, truncated path, extra path elements, a graph leaf offered to the policy
  tree (fails through the `tree` label).
* **Policy tree leaf**: `{"tree":"policy","id":INV,"digest":H,"enabled":bool,"source":"std"|"custom"}` for **every**
  `invariants` row, enabled or not (rows are archived, never deleted). `source` is the row's `source`.
* **Blind-spot tree leaf** (one tree per result): `{"tree":"blind","inv":INV,"node":<node ref>,"direction":"in"|"out"|"both"|"host","reason":<str>,"relevant":bool,"collector"?:<str>}`
  for each entry of the **full** in-memory `Result.blind_spots`, before `compact_result`'s cap. Node refs are private
  data and appear only inside blinded leaves.
* **Graph tree** (one tree, built from the **same document object the engine evaluated**). Leaves, all with
  `"tree":"graph"`:
  * `{"t":"node", ...}`: each element of `doc["nodes"]` minus its `coverage` and `facts` keys (so `id`, `kind`, `zone`,
    `zone_unknown`, `class`, tags and every other label the loader emits are committed).
  * `{"t":"edge", ...}`: each element of `doc["edges"]` (after CIDR expansion).
  * `{"t":"cov","node":<id>, ...}`: each coverage record of each node minus `observed_at`.
  * `{"t":"fact","node":<id>,"name":<collector>,"d":H}`: each host fact, where `d` is the sha256 of the engine's own
    meaning view of the entry (`store.digest_view(name, entry)` encoded with the engine's frozen encoder, the same
    bytes `graph_loader.doc_sha` hashes). The verifier treats `d` as opaque; the spec describes the recomputation
    informatively. Fact `data` may contain non-ASCII text, which is why the leaf carries a digest, never the data.
  * `{"t":"meta","k":<key>,"v":<value>}`: any other top-level key of the document except `now` (forward compatibility
    with P2.1 document growth).
  * Exclusion rule, identical to `graph_loader.doc_sha`: the document's `now`, coverage `observed_at`, and the
    provenance keys `store.digest_view` removes. This keeps roots stable across pure refreshes (freshness is covered by
    `valid_until`) and matches "did the input change".
  * Encoding rule for leaf values: a key with value `None` is **omitted**; a string outside the PCJ charset is
    replaced by `{"$h":"sha256:<hex of its UTF-8 bytes>"}`; anything else outside PCJ (a float, a negative integer, a
    non-string key) makes the issuer **fail closed** (`graph_unencodable`: no statement, an alert; the previous one
    lapses). A lossy encoding is never used.
  * `snapshot.graph.size` is the leaf count. A graph above `PADDOCK_ATTEST_GRAPH_LEAF_CAP` (default 500 000, about 7 s
    of hashing in a thread) is not attested (`graph_too_large`).
  * What the root does and does not give: it binds the issuer to one graph (non-repudiation), lets the owner disclose
    chosen leaves to an auditor who can compare them with their own observation, and lets consumers see "the graph
    changed" when roots differ. It does **not** prove the graph is true, and it leaks only coarse size and change timing.

### 2.4 DSSE PAE

`PAE(type, payload) = b"DSSEv1 " + dec(len(type)) + b" " + type + b" " + dec(len(payload)) + b" " + payload`, lengths
are ASCII decimal **byte** counts with no leading zeros and single `0x20` separators. `type` is the envelope's
`payloadType`, which MUST equal the expected constant for the document kind:

| Document | `payloadType` |
|---|---|
| statement | `application/vnd.in-toto+json` |
| key cert (all usages) | `application/vnd.paddock.key-cert+json` |
| revocation list | `application/vnd.paddock.revocation-list+json` |

Signing the base64 text or the raw payload instead of the PAE is the classic bug; vectors `sig-over-raw-payload` and
`sig-over-b64-text` pin it. Signature contexts are mutually non-prefix: `DSSEv1 ` (statements, certs, revocation
lists), `paddock-anchor/v2\n` (anchors), `paddock-agent-envelope/v1\n` and `paddock-enroll/v1\n` (P2 agent), so a
signature in one context can never verify in another.

### 2.5 Ed25519 rules (every implementation, before calling its library)

Accept only 64-byte signatures and 32-byte public keys. Reject `S >= L` (little-endian bytes 32 to 63) as
`sig.noncanonical_s`. Reject a public key that is not a canonical point encoding or is one of the 8 small-order points
as `sig.weak_key`. `R` is not pre-checked: the residual cofactor ambiguity needs a malicious signer, which here is
a certified key (documented in the spec). Vectors: RFC 8032 tests 1 to 3, `S + L`, identity key with identity
signature, a 2-torsion key.

### 2.6 Time

Instants compare as integers (seconds since epoch) parsed by a hand-written parser (Python's `fromisoformat` varies by
version). Windows are **end-exclusive**: valid iff `issued_at - 300 <= now < valid_until`. Producers floor engine
timestamps to whole seconds (flooring is conservative for `valid_until`). Durations in policy: `<int>(s|m|h|d)`.

### 2.7 Frozen legacy encodings (informative)

Invariant digests and fact digests are `sha256` over `json.dumps(sort_keys, separators=(",", ":"),
ensure_ascii=True)` of the engine's model dump and may contain a Python float (`coverage.require` serialises as
`1.0`). That is not PCJ and **must not be changed** (stored digests and std-copy matching depend on it). To the
verifier they are opaque `sha256:<64 hex>` ids.

## 3. Keys, certificates, backends, anchor

### 3.1 Hierarchy

```
attestation ROOT   (offline, Ed25519, ceremony script, 10 y, pinned in the verifier release)
   |-- certifies, offline, yearly -->
ISSUER  (online, usage issue-cert, 1 y)      REVOKER (online, usage revoke, 1 y)
   |-- certifies, online -->
estate ATTEST key (usage attest, signs statements)   estate ANCHOR key (usage anchor, signs anchors)
```

* The root is **not** the license key (`vendor_key_ceremony.py`). A new script `scripts/attest_root_ceremony.py`
  (same safety rules: never writes inside the repo, passphrase of 16+ characters, never overwrites, self-test through
  the real verifier) has subcommands `generate-root`, `certify-issuer`, `certify-revoker`, `fingerprint`, `check`
  (reads the root back from a built wheel). The existing license script is not edited.
* `trust_roots.json` (verifier data, **empty in a source build**): `[{"kid","public_key"(base64),"usage":"root"|"issue-cert","not_before","not_after"}]`. A source build with no
  roots exits 2 `config.no_trust_roots` unless `--roots` is given; a self-hoster pins its own issuer (`usage:"issue-cert"`)
  and uses chain length 1.
* The platform issuer/revoker private keys are loaded from `PADDOCK_ATTEST_ISSUER_KEY_FILE` /
  `PADDOCK_ATTEST_REVOKER_KEY_FILE` (PKCS8 PEM encrypted with `PADDOCK_ATTEST_PLATFORM_KEY_PASSPHRASE`) with their
  certs in `..._CERT_FILE`; a KMS handle is a stub. Missing material means `state: not_configured` and no key can be
  created (no ephemeral keys).

### 3.2 Certificate format

DSSE envelope, `payloadType` `application/vnd.paddock.key-cert+json`, one signature by the parent key, payload (PCJ):

```json
{"_type":"https://paddock.dev/key-cert/v1","alg":"ed25519","custody":"hosted","estate":"e_3fq7m2xk5h6cnj4d2v5yb7wzta",
 "issuer_kid":"<parent kid>","kid":"<32 hex>","not_after":"2027-03-01T00:00:00Z","not_before":"2026-12-01T00:00:00Z",
 "public_key":"<base64 of the raw 32 bytes>","serial":17,"usage":"attest"}
```

* `usage` is `attest`, `anchor`, `issue-cert` or `revoke`. `estate` is present for `attest` and `anchor` and absent
  otherwise. `custody` is `hosted`, `byok-kms` or `byok-hsm`. There is **no domain** in a cert (domains change and a
  cert would enumerate them).
* `kid` MUST equal `sha256(public_key)[:32]` (`key.fingerprint_mismatch`). A child's window is clamped to its parent's.
  Every cert in the chain MUST be valid at the statement's `issued_at`, not at "now".
* Windows: root 10 y; issuer and revoker 1 y; **estate key 365 d (rotate at 300 d, 30 d overlap); cert 90 d, renewed
  at 60 d with the same key** (a new serial). Rationale: the DNS record pins the key fingerprint, so a key rotation
  costs the customer a DNS edit but a cert renewal must be free. Exposure after a compromise is bounded by
  revocation plus the 24 h statement life, not by key age.

`keys.json` (public, unsigned wrapper; every cert is signed):

```json
{"spec":"paddock-keys/v1","estate":"e_...","issuers":[<issuer cert envelope>],"revoker":<revoker cert envelope>,
 "keys":[{"kid":"...","usage":"attest","alg":"ed25519","public_key":"<b64>","custody":"hosted","not_before":"..","not_after":"..","cert":<cert envelope>}]}
```

The cert payload is authoritative; every unsigned entry field MUST equal it (`key.cert_subject_mismatch`); duplicate
kids are `keys.invalid`. Key `status` is deliberately not in the file (mutable, unsigned).

### 3.3 Rollover choreography (hosted)

T-30 d: create key K2 (`pending`) and its cert; the API returns the second TXT record. The server observes K2 in DNS,
requiring two observations at least `min(TTL, 1 h)` apart, then activates K2 (signing switches). K1 becomes `retiring`
until its last statement's `valid_until` plus 48 h has passed, then `retired`; its sealed secret is deleted 7 days
later. K1 stays in `keys.json` (history verification) and its TXT record may be removed after 2 x TTL. At most 3
kids are in DNS at once (active, next, previous). Key status moves only forward: `pending -> active -> retiring ->
retired`, any -> `revoked`, `revoked` terminal (trigger-enforced).

### 3.4 Revocation list (`revoked.json`)

DSSE, `payloadType` `application/vnd.paddock.revocation-list+json`, signed by the **revoker** key (or the issuer key);
the signer's cert is in `keys.json` (`revoker`) and chains to a pinned root:

```json
{"_type":"https://paddock.dev/revocation-list/v1","estate":"e_...","seq":42,"issued_at":"<T>","next_update":"<T, issued_at + 24 h>",
 "revoked":[{"kid":"<kid>","reason":"key_compromise"|"superseded"|"cessation","revoked_at":"<T>"}],
 "superseded":[{"subject":"dns:example.com","min_seq":1843,"at":"<T>"}]}
```

* `key_compromise` rejects **every** statement signed by that key regardless of its claimed `issued_at`;
  `superseded` and `cessation` reject only statements with `issued_at >= revoked_at` (older ones warn
  `key.revoked_superseded`).
* `superseded[]` rejects statements of that subject with `seq < min_seq` (`chain.superseded`). It is written on every
  downgrade flip (section 5.5) and also when the issuer loses the ability to evaluate and cannot issue (then
  `min_seq = last_seq + 1`, meaning "no statement at or above this exists"). One entry per subject, at most 11.
* `seq` never goes backwards against a cached copy. A missing list is `revocation.missing` (UNVERIFIABLE), one that
  fails verification is `revocation.unverifiable`, one with `now > next_update + 48 h` is `revocation.stale`
  (UNVERIFIABLE, never accept). The list is mandatory in every bundle and re-signed at least daily even when
  unchanged. The consumer policy `revocation: best_effort` downgrades these to warnings and the output then says
  "revocation NOT checked".
* Honest bound: revocation latency is up to the list's age; an offline copy of a statement is bounded by its own
  `valid_until`.

### 3.5 Private-key storage (hosted custody)

* `PADDOCK_ATTEST_KEK` (32 bytes urlsafe base64) or `PADDOCK_ATTEST_KEK_FILE`, plus `PADDOCK_ATTEST_KEK_PREVIOUS`
  (comma list) for rotation; the KMS-wrapped production variant (`PADDOCK_ATTEST_KEK_KMS_KEY_ID`) is a stub. It is
  deliberately **not** `PADDOCK_SECRET_KEY`. Without a KEK key creation is refused.
* Sealing: wrap key `HKDF-SHA256(KEK, salt="<tenant>|<kind>|<kid>", info=b"paddock-attest-key-wrap/v1")`,
  AES-256-GCM, AAD `paddock-attest-key/v1|<tenant>|<kind>|<kid>|<usage>|<alg>`, blob
  `v1:<kek_id8>:<b64(nonce|ciphertext|tag)>`. `kind` is `signing` or `commit`. Swapping a blob between tenants, kinds,
  kids or usages fails authentication.
* `sign()` re-derives the public key from the unsealed seed and checks the `kid`, and verifies its own signature before
  returning (guards a swapped `public_key` column and fault injection). Unsealed keys are never cached; the seed is held
  in a `bytearray` zeroed in `finally` (best effort in CPython); never logged. `repr(KeyHandle)` never shows secrets
  and the handle carries identity only, **not** the sealed blob (a handle that carried it made `destroy()` a no-op in
  the probe).
* Honest limit: a compromised orchestrator process holds the KEK in memory. Hosted custody means Paddock can sign;
  the cert's `custody` field says so, and BYOK/KMS is the answer.

### 3.6 `KeyBackend` contract (`attest/backend.py`)

```python
class KeyBackend(Protocol):
    name: str; custody: Literal["hosted","byok-kms","byok-hsm"]
    algs: frozenset[str]; max_message_bytes: int | None        # None = unlimited
    async def generate(self, tenant_id, usage, alg) -> tuple[KeyHandle, bytes]   # handle, raw public key
    async def sign(self, h: KeyHandle, message: bytes) -> bytes                  # message = the full signing input
    async def destroy(self, h: KeyHandle) -> None
    async def health(self, h: KeyHandle) -> BackendHealth
# no export/get_private/dump surface. Errors: BackendError, BackendUnavailable (timeout, throttling), BackendKeyDisabled, MessageTooLarge
```

The contract suite (`test_attest_backend_contract.py`, parametrised over every backend including a fake KMS) asserts:
sign verifies under the returned key; Ed25519 deterministic; no attribute matching export|private|dump|secret;
`repr(handle)` leaks nothing; two keys independent; the algorithm allow-list is enforced; destroy then sign fails;
`BackendUnavailable` propagates (the issuer must not issue); a message over the cap raises `MessageTooLarge`; a
wrong-tenant handle cannot sign; health reflects a disabled key.

### 3.7 Audit anchor v2

**The trap**: `Anchor.signed_body()` is `asdict(self)` minus `sig`. Adding any dataclass field puts a new key into the
signed bytes of every legacy anchor (`"sigs":null` appears), so every stored HMAC anchor would verify as
`bad_signature`, fail closed `audit.verify()` and `anchor_head()` for every tenant, and Object-Lock objects cannot be
rewritten. Hence:

```python
@dataclass
class Anchor:
    tenant_id; max_id; head_hash; hash_alg; ts; v: int = 1; kid=None; sig=None     # unchanged legacy fields
    sigs: list[dict] | None = None   # NEW: [{"v":2,"alg":"ed25519","kid":"<32hex>","estate":"e_...","at":"<T>","sig":"<b64>"}]
    def signed_body(self):           # LEGACY bytes, byte-identical: also pop "sigs"
    def to_json(self):               # omit "sigs" when None (a legacy-only anchor serialises exactly as before)
```

* `v` stays 1 (it is inside the legacy signed bytes). Sinks (file, S3 Object Lock, webhook) are **unchanged**; a dual
  anchor is a bigger JSON object under the same key scheme. An old binary during a rolling deploy ignores `sigs` and
  its HMAC check still passes.
* **Public anchor doc** (bundle `anchors/<max_id>.json`, PCJ):
  `{"alg":"ed25519","at":"<T>","estate":"e_...","hash_alg":"sha256"|"hmac-sha256","head":"<64 hex>","kid":"<KID>","max_id":N,"sig":"<b64>","v":2}`.
  `at` is the legacy `ts` floored to whole seconds; `hash_alg` is the **family only** (the HMAC key id of
  `hmac-sha256:<kid>` is not published); `estate` replaces the tenant UUID. Signature input =
  `b"paddock-anchor/v2\n" + PCJ(doc without sig)`, by the estate's `anchor` key. `audit_anchor.digest` in a statement is
  `sha256(PCJ(doc including sig))`.
* **Signing hook** (about 12 lines in `audit.py`): module-level `ANCHOR_SIGNERS: list[Callable[[pool, Anchor], Awaitable[None]]]`;
  `anchor_head()` calls each after `sign_anchor()` and before `sink.publish`. `attest/anchor_sig.py` registers one at
  startup; it enters the tenant context itself, finds the estate's active `usage=anchor` key, signs through the
  backend, stores the public doc in `attest_anchors`, and **on any failure logs and publishes the legacy-only anchor**.
  The anchor key is always hosted, even for BYOK estates (hourly KMS calls would make a core integrity control depend
  on a customer's KMS).
* **No silent downgrade.** `audit.verify()` calls `anchor_sig_status(anchor)` when `sigs` is present: every listed
  signature from a known key must verify under the pinned vendor chain (using verifier cert code, not just a DB key
  row, because a DB writer can also replace a key row; `attest/certs.py` `verify_chain`, built on the P3.1 primitives and cross-checked by the P3.4 vectors); any failure is `bad_signature` (fail closed). With `sigs`
  absent the legacy path is allowed only while `AUDIT_ANCHOR_ALLOW_LEGACY=true` (default) **and**
  `attest_estates.anchor_v2_since` is NULL; after the first v2 anchor that column is set (sticky) and a later anchor
  without `sigs` is `anchor_downgrade` (fail closed). The environment flag lives outside the DB, so a DB attacker
  cannot undo it.
* **What an outsider can verify** (and the wording must say no more): (1) the anchor signature verifies under a
  certified, unrevoked estate `anchor` key; (2) its `estate` equals the statement's; (3) `at <= issued_at` and
  `issued_at - at <= 2 h` (`--max-anchor-age`; the issuer anchors on demand right before signing, so the real gap is
  seconds); (4) `max_id` and `at` never decrease across statements and no two anchors share a `max_id` with different
  `head`; (5) with an independent copy of the sink (read-only Object-Lock listing, an auditor's mirror:
  `--anchor-file`) a byte comparison, which is the only check that survives a compromised orchestrator.
  **Not verifiable by an outsider**: that the audit rows are intact (the chain is keyed HMAC, the key never leaves the
  orchestrator) or that a given policy edit is in the log. An auditor with `audit_export` and the escrowed HMAC key can
  check that, and the `attest.commit` row (section 5.4) makes the link findable. Never describe the chain as "publicly
  verifiable".

### 3.8 Compromise levels (cheapest first)

1. Global kill: env `PADDOCK_ATTEST_ISSUING=false` (authoritative at start) and a Redis key polled each tick
   (convenience; an unreachable Redis does **not** stop issuing).
2. Tenant suspend: `POST /v1/attestations/suspend` sets `issuing_suspended`; no issuing, hosted objects stay up until
   `valid_until` and then verify as expired.
3. Key emergency revoke: `POST /v1/attestations/keys/{kid}/revoke` in one transaction: key `revoked`, append
   `attest_revocations`, `hold_reason='key_compromise'` (ack required), publication objects `public=false`
   immediately (fail safe: stop serving statements of that key before the new list is signed), sealed secret deleted,
   backend `destroy`; then re-sign `revoked.json` and push it **first**. A new key is generated `pending`; issuing
   resumes after an admin ack and DNS naming the new key.
4. Vendor side: `scripts/attest_vendor_admin.py` (DB owner role, bypasses RLS): `revoke-key`, `suspend-tenant`,
   `global-kill`, `revoke-issuer` (root-signed list plus a verifier release).
5. Issuer compromise: root-signed issuer revocation, new issuer cert, re-certify every estate key (cheap, same keys).
   Root compromise: new root plus a verifier release (`--min-root-epoch`). Documented in the ops runbook, not
   automatable. Exposure after an estate-key compromise is `min(24 h, list propagation)`; the verifier's staleness rule
   bounds the rest.

## 4. DNS key binding

### 4.1 Record

`_paddock-attest.<domain>` (exact name, no parent climbing: `app.example.com` publishes under
`_paddock-attest.app.example.com`), TXT:

```
v=1; kid=<32hex>; fp=sha256:<64hex>[; keys=https://.../keys.json]
```

* `fp` = sha256 of the raw 32-byte public key; `kid` = its first 32 hex (redundancy is checked, so a hand edit cannot
  disagree). `keys` is optional (default `https://<domain>/.well-known/paddock/keys.json`); for Paddock-hosted bundles
  the generator emits `keys=<PADDOCK_PUBLIC_BASE_URL>/v1/public/attest/<domain>/keys.json`. The bundle root is the
  directory of the `keys` URL. It is a **location hint only**: everything fetched is authenticated by cert and `fp`,
  never by transport.
* Sizes (measured): minimal 117 bytes, hosted short domain 189, 60-character domain 237. The generator hard-fails above
  450 bytes and warns above 255 (split strings are legal and joined with no separator). Three records (active, next,
  previous) is about 600 bytes, under the EDNS budget.
* **Parser rules** (one implementation, `paddock_verify/dns/txtparse.py`, imported by the server): chunk strings of one
  record are concatenated; fields are `;`-separated `key=value` with optional single spaces; keys are lowercase; a
  duplicate key makes the record malformed; unknown keys are ignored; `v != 1` ignores the record (forward
  compatibility); `kid` not a prefix of `fp` or a non-https `keys` is malformed; a malformed record is ignored with
  warning `dns.record_ignored`; more than 8 `_paddock-attest` records or more than 4 KiB in total is
  `dns.too_many_records` (reject, DoS guard).

### 4.2 Server side (`attest/dns_binding.py`)

* `POST /v1/attestations/domains {domain}`: normalise (lowercase, IDNA to punycode, no trailing dot, no IP literal,
  labels <= 63, total <= 253), find the eligible scope entry (5.6), create `attest_domains(binding_status='pending')`,
  return the TXT records to add (`name`, `type`, `ttl` 300, `value`, `kid`, `role` active or next), `size_bytes`,
  `warnings`.
* The check is one TXT query through a new `lookup_txt_rrset(name)` returning `TxtAnswer{strings, ttl, ad, rcode}`
  (`scope_proof.lookup_txt` drops TTL and the AD flag so it is not reused; `scope_proof.py` itself is not edited).
  `search=False`, TCP fallback on truncation, 5 s timeout, the same politeness limiter as scope proofs. No HTTP fetch
  of `keys=` (not needed, avoids SSRF).
* `verified` iff at least one record parses and names a kid that is one of this estate's active, next or retiring
  keys with a matching `fp`. Other kids are ignored (rollover) except: the same kid with different `fp` is `conflict`
  (fail); zero records is `absent`; only foreign kids is `foreign_key` (fail); a foreign kid next to ours is fine
  (legitimate co-hosting).
* Evidence stored: `{observed_at, ttl, records, matched_kid, ad, resolver}`. `ad` is stored only when
  `PADDOCK_ATTEST_DNS_RESOLVERS` names validating resolvers and `PADDOCK_ATTEST_DNS_TRUST_AD=true`, else null. DNSSEC is
  **reported, never required**, by the server.
* Re-check every 6 h (`attest_dns_recheck_hours`), hourly while failing, jittered, batch 20. Failing for more than
  `attest_dns_grace_hours` (6) turns `binding_status` to `failed`, `serving=false` and the hosted bundle disappears
  (uniform 404); it resumes automatically when the record returns. The owner's `published` flag is never changed by the
  job. Reason: a sold or lapsed domain must stop being served; the verifier's own DNS check is the real authority, so
  this is hygiene with a short grace.

### 4.3 What the verifier checks without trusting Paddock

1. Resolve the TXT with **its own** resolvers (never Paddock). Interface: `Resolver.resolve_txt(qname, timeout) ->
   DnsAnswer{status: ok|nxdomain|nodata|servfail|timeout|error, txt: [str], ad: bool, source: str}`. Implementations,
   all stdlib: `doh:<url>` (RFC 8484 wire format, hand-built query with EDNS0 DO=1, name-compression pointers handled,
   4 KiB cap; default set Cloudflare and Google), `udp:<ip>[:port]` (TCP fallback on TC), `system`, `file:<path>`
   (offline and tests; several named resolvers so a disagreement vector is expressible), and an injectable fake.
2. **Quorum**: all configured resolvers that answer must agree; at least `--dns-min-resolvers` (default 2 for the
   default DoH set, else 1) must answer (`dns.insufficient_resolvers`, UNVERIFIABLE); disagreement is
   `dns.resolvers_disagree` (UNVERIFIABLE, never "accept the one that matches").
3. Parse; pick the records whose `kid` equals the signing key's kid. None: `dns.no_binding` (NXDOMAIN, NODATA or no
   valid record: reject). SERVFAIL, timeout, transport failure: `dns.lookup_failed` (UNVERIFIABLE).
4. `fp` equals sha256 of the public key **in the cert**, the cert's key verifies the statement, the cert chains to a
   pinned root, and the revocation list is fresh and does not list it. A different `fp` for the matching kid is
   `dns.mismatch`; the same kid with two fps is `dns.record_conflict`.
5. Report `dnssec`: `ad_asserted` / `not_asserted` / `unknown` (AD is the resolver's claim over a TLS channel). Policy
   `dnssec: required` without AD is `dns.dnssec_unproven` (UNVERIFIABLE).
6. A retired key's old statements verify in `--history` mode with the binding reported `key_retired`. Offline mode:
   `--dns-record "<txt>"` (operator supplied) is reported as asserted-by-operator and is UNVERIFIABLE
   (`dns.skipped_offline`) when the policy requires DNS. A statement whose subject is `paddock-estate:` has no domain to
   bind: `dns.not_applicable` (warning), and a policy requiring DNS rejects it.
7. Privacy note (in the spec): the resolver sees which domain is being verified.
8. Residual risk, stated: a registrar or DNS compromise defeats the domain anchor; the vendor cert is the second,
   independent anchor, and both are required by default.

## 5. Issuing, storage, scheduler

Module root: `orchestrator/app/attest/`. Everything runs inside `tenancy.tenant_context(tid)`; no SQL names
`tenant_id` (the pool stamps it, as in P1/P2).

### 5.1 Estate and publications

* **Estate** (`attest_estates`, one row per tenant, created lazily and idempotently by `estate.ensure_estate()` on the
  first attestation action): random `estate_id` (`e_` + base32-lowercase of 16 random bytes, 26 characters), the sealed
  `commit_key`, the first `attest` and `anchor` keys with certs, the default publication
  `paddock-estate:<estate id>`, and the settings/holds/lease columns. Without issuer material or a KEK the estate is
  `not_configured` and nothing is created.
* **Publication** (`attest_publications`): `(estate, subject)` with `verdicts` (`holds_only` default | `all`),
  `disclose_custom` (false default), `published` (false default), `serving` (derived, 6.2), and its own `last_seq` chain.
  Statements are issued for **every non-archived publication, published or not** (an unpublished statement is stored
  privately and only previewed or exported). A domain publication requires a verified `attest_domains` binding before
  `published` can be true. Limits: 1 estate publication, 10 domain publications.

### 5.2 Snapshot and evaluation (`attest/snapshot.py`, `attest/engine_adapter.py`)

Verdicts are produced by a **fresh single-snapshot evaluation** (D1). One pass per estate, then one statement per due
publication from the same in-memory result set. The pass writes **nothing** to `invariants.last_*`, `invariant_runs` or
`findings`.

1. One `REPEATABLE READ READ ONLY` transaction. `now` = DB `now()` floored to the second = `snapshot.at` and the `now`
   passed to `evaluate()`.
2. Load the graph with `runner._load_snapshot(pool, now)` and apply `runner._parse_graph(snap, summary)`; both are
   imported **only** by `attest/engine_adapter.py`, which a test pins by name and behaviour (CIDR-expansion overflow
   gives `graph_incomplete`; `zone_unknown` with an old library gives `graph_unavailable`; `ReachGraph.from_dict`
   errors give `graph_unavailable`). A renamed helper makes the pin test fail loudly instead of silently dropping the
   guards. P2.1 is asked (via the lead) not to rename them or to expose public aliases; if aliases appear the adapter
   switches to them.
3. If there is no usable graph, or the graph is above the leaf cap or unencodable (2.3), **there are no results**:
   nothing is attestable. The issuer does not publish a statement without a graph commitment; it signs the
   `superseded[]` entry (3.4) so a verifier that fetches the list rejects the older HOLDS, and the older statement
   otherwise lapses at its `valid_until`.
4. Read **all** `invariants` rows (enabled and disabled, `source`, `digest`, `version`, `yaml`), `count(*)` of
   `invariant_versions`, and the shipped std digests (`paddock_assurance.stdlib`).
5. For each enabled row: `compile_text(yaml)`; require `plan.digest == row.digest`, else the row is
   `invalid_definition`. For `source='std'` also require `row.digest ==` the shipped digest of that std id, else the row
   is `std_unrecognised`.
6. `evaluate(plan, graph, now)` for each, in `asyncio.to_thread` under the runner's own time budget. Any exception is
   `evaluation_error`, never HOLDS. The Merkle trees are built in a worker thread too (about 0.014 ms per leaf in
   pure Python: 1.4 s at 100k leaves).
7. **Determinism guard**: if `invariants.last_result.doc_sha ==` the current `graph_loader.doc_sha(doc)` then the
   stored verdict class MUST equal the fresh one. A mismatch withholds that result and writes a log line and the audit
   row `attest_divergence`; the issuer does not touch the runner (its own backstop re-evaluates). The stored result never
   upgrades a fresh one and is never the source.
8. Per result also compute: `selected` sizes (`ReachGraph.select` on the invariant's `from_`, `to`, `via.stop_at`
   selectors; for `host-config`, `Result.hosts["selected"]`), `exceptions = len(exceptions_used)`, the blind-spot tree
   over the full `Result.blind_spots`, and the mapping of `reasons` to `reason_codes`.

### 5.3 Publish gates (a result enters `results` only if it passes all)

Failing a gate is **withholding** (visible only through the counts) in `holds_only` mode. In `all` mode a result that
cannot be produced is published as `UNKNOWN` with the matching reason code, with two exceptions that **refuse the whole
issuance** (`issue.refused`, an alert): a `std:` row whose digest is not the shipped one, and a VIOLATED result whose
`violation_count < 1` (an engine inconsistency).

| Gate | Rule |
|---|---|
| G1 | compiled, digest equals the row, evaluated without exception |
| G2 | verdict allowed by `verdicts`: `holds_only` publishes HOLDS only; `all` publishes HOLDS, VIOLATED, UNKNOWN |
| G3 | `source='std'` rows only, unless `disclose_custom`; a `std:` id appears only when `source='std'` and the digest is the shipped one |
| G4 | (HOLDS) `evidence_tier` is not None, `valid_until` is not None and `valid_until - issued_at >= 15 min` |
| G5 | (HOLDS) tier `>= max(min_tier, configured)` and `<= cap(assertion)` (`configured` for host-config, else `observed`, further capped by `ATTEST_MAX_TIER`); `declared` never; `tested` never until P5 |
| G6 | (HOLDS) `relevant_universe >= 1`, `relevant_covered * 10000 >= required_bp * relevant_universe`, `selected.to >= 1` |
| G7 | the determinism guard of 5.2 step 7 passed |
| G8 | the graph is complete and encodable (5.2 step 3) |

The verdict class is never changed by the issuer: UNKNOWN is never published as HOLDS and VIOLATED is never
downgraded. The tier is copied from `Result.evidence_tier`; the issuer never computes it and never takes it from
`min_tier`.

### 5.4 Issuing procedure (order matters)

Per estate pass, then per due publication:

1. **Preconditions** (5.7); the pass takes a lease on the estate row (`lease_until` 120 s, owner = replica id) so N
   replicas never evaluate the same estate; a replica that loses the lease skips.
2. **Snapshot and evaluation** (5.2). Compute the policy tree and counts: `total` = all rows, `enabled_std`,
   `enabled_custom`, `disclosed` = `len(results)`, `versions` = `count(invariant_versions)`.
3. **Commit-then-anchor**: write the audit row `attest.commit {publication, seq_next, policy_commitment, graph_root}`
   (own committed transaction) **before** `audit.anchor_head(pool, sink, tenant_id)` so the anchor head covers that
   row. An auditor holding the chain can match the commitment in the statement to a row at or below `anchor.max_id`.
   `AuditIntegrityError` refuses the issuance and sets `hold_reason='audit_integrity'` (ack required: a chain tamper is
   not self-clearing). A sink outage refuses and retries when `PADDOCK_ATTEST_REQUIRE_ANCHOR` is true, else the
   statement omits `audit_anchor`. An anchor with only the legacy HMAC signature counts as absent. Orphan `attest.commit`
   rows after a failed issue are harmless (bounded by the backoff).
4. **Write transaction**: `pg_advisory_xact_lock(hash('attest', publication_id))`; `SELECT ... FOR UPDATE` the
   publication; `UPDATE attest_publications SET last_seq = last_seq + 1 RETURNING last_seq`; read `prev` =
   `statement_digest` of seq-1 in the same transaction; `issued_at` = floor of the DB `now()`; require
   `snapshot.at <= issued_at <= snapshot.at + 900 s` and `anchor.at <= issued_at` (else abort and re-snapshot);
   `valid_until = floor(min(issued_at + ttl, key.not_after, attest cert not_after, issuer cert not_after))`, refusing
   when it is under `issued_at + 15 min`; build the PCJ payload; **sign inside the transaction** through the backend
   (10 s timeout, `MessageTooLarge` refuses) so a sign failure rolls back the seq bump and the chain has no gaps.
5. **Self-verify** (D21): `paddock_verify.verify_envelope(envelope, keys=this estate's keys.json, roots=pinned,
   now=issued_at, mode=issuer_selfcheck)` runs steps 0 to 8 and 10 of section 8.3 with DNS skipped and the live
   revocation list. Any failure rolls back, increments `attest_self_verify_failed`, and sets `hold_reason='self_verify_failed'`
   (ack required).
6. Insert `attest_statements` (`UNIQUE (tenant, publication, seq)` is the backstop), insert the encrypted disclosure
   material (5.9), render and upsert the bundle objects (6.1) and update the publication head and `serving`; write the
   audit row `attest.issued {seq, statement_digest, kid, disclosed, total, verdict_counts}` in the same transaction;
   commit.
7. After commit: publish the event `attestation_issued` via `queue.publish_event`, enqueue push jobs, prune bundle
   history beyond 60 objects (the ledger keeps everything).

Idempotency: `POST /v1/attestations/issue` honours an `Idempotency-Key` header stored in
`attest_statements.idempotency_key` (unique per publication) and returns the stored statement on replay; the loop path
is idempotent through the trigger comparison of 5.5. After a database restore the publisher MUST read the remote
`attestation/latest.json` and continue from `max(local, remote) + 1`; if the remote cannot be read it refuses to issue.
Two different payloads under one `(publication, seq)` are **equivocation** and are reported by any verifier that sees
both.

### 5.5 When to issue (`attest/loop.py`, 60 s tick, per-tenant isolation like `assurance.tick_once`)

The loop never calls the runner and never changes assurance state. Change detection uses the stored rows only as a
trigger: `trigger_digest = sha256(sorted (invariant_id, digest, enabled, last_verdict, status_at(now), evidence_tier,
relevant covered/universe from last_result) + policy counts + kid)`, compared with
`attest_publications.trigger_digest`.

| Condition | Action |
|---|---|
| no head statement, or a hold was cleared | issue at the next tick |
| age `>= ttl/4` (6 h at the default) | refresh |
| **downgrade**: a disclosed HOLDS is gone, worse (verdict, tier, digest) or no longer publishable; policy edit or disable removed it | issue immediately (at most 1 per 60 s per publication) **and** sign `superseded[{subject, min_seq=new seq}]` |
| **upgrade or other change**: a new HOLDS, coverage change, policy counts, key change | debounced: at most one per 300 s |
| loss of the ability to evaluate (graph incomplete or unencodable, library missing) while a HOLDS is live | cannot issue a graph commitment: sign `superseded[{subject, min_seq=last_seq+1}]`, alert, let the head lapse |
| nothing changed and the head has more than 3/4 of its life left | no-op |

Minimum spacing between statements of one publication is 300 s except for downgrades. Budget 288 signatures per
publication per day. A statement is skipped when its `valid_until` would be under 15 minutes away.
`GET /v1/attestations/status` returns `lapses_at` and `limiting_invariants[]` (which invariant and which evidence bounds
it): a weekly external scan against `max_age: 24h` makes a HOLDS lapse daily, a cadence knob the operator must see and
the issuer cannot fix.

### 5.6 Subjects and the scope digest (`attest/scope_digest.py`)

* Subject of a domain publication: `dns:<domain>`, allowed only for a domain with an active, unexpired
  `scope_entries` row that is proven: kind `domain` with proof status `verified` (method `dns_txt` or `http_file`), or
  a strict subdomain of an active `subdomain_wildcard` entry with proof `verified` (`dns_txt` only); read through
  `scope_proof.fetch_proof_row`. `attested` does not apply to domains. Subject of the estate publication:
  `paddock-estate:<id>`.
* **Scope document**: `{"v":1,"entries":[{"kind":..,"value":..},...]}` sorted by (kind, value), PCJ, sha256. Entries:
  active, unexpired, proof status `verified` or `attested`, normalised (domains lowercase A-label with `*.` kept for
  wildcards, CIDRs through `ipaddress.ip_network(strict=False)` canonical text, ASNs `AS<n>`). **Non-global (private)
  CIDRs are excluded** from the digest (an unsalted digest of internal ranges would be guessable) and only counted in
  `scope.private`; active entries without a proof are excluded and counted in `scope.unproven`; `scope.entries` is the
  number included. The scope digest is **not** the coverage universe (that comes from assets, connectors and agents),
  which is why the coverage integers and limits item 3 exist. The owner may publish `scope.json` (the document) in the
  bundle so anyone can check the digest.
* A statement containing `dns:victim.com` is accepted for victim.com only if victim.com's own DNS record names this
  `kid` (confused-deputy defence, 4.3).

### 5.7 Preconditions and failure matrix

All must hold; any failure means **do not issue** (the existing statement lapses naturally), with one rate-limited audit
row `attest.issue.refused{reason}` (first per reason per 6 h with a `suppressed` count).

1. Not killed or suspended; no unacked hold; license: `assurance` for private issuing, `attestations_public`
   additionally for a `published` publication (same lookup as `runner._entitled`, but a lookup **failure fails closed**
   here: issuing is the outward claim; the runner fails open).
2. An active `attest` key whose window contains `issued_at`, a valid cert chain, a healthy backend
   (`BackendUnavailable` refuses, backoff 60 s to 15 min).
3. At least one enabled invariant; `paddock_assurance` and `paddock_verify` importable.
4. For published publications: scope proof verified, DNS binding verified, the active key named in DNS.
5. Size: payload at most 256 KiB, results at most 256, backend `max_message_bytes` respected. Never truncated.

| Condition | Behaviour |
|---|---|
| backend timeout or unavailable, issuer cert expired | no issue; status `degraded`; exponential backoff; at most 1 audit row per hour per reason |
| evaluation error for one invariant | that invariant is UNKNOWN (published in `all` mode) or withheld; never HOLDS |
| all HOLDS evidence lapsed | issue only if something changed; no HOLDS ever carries an expired `valid_until` |
| license lost | stop issuing; hosted objects keep serving the last statement until it expires (the verifier says "expired", more useful than a 404) |
| audit chain broken | refuse and hold (ack) |
| self-verify fails | rollback and hold (ack) and metric |
| serialization failure or unique conflict | retry once, then skip the tick |

### 5.9 Retention and disclosure material

* `attest_statements` append-only; application retention 400 days (matches anchor Object-Lock retention), done by
  `attest/loop.py` itself (no edit to `retention.py`); the SQL floor is 90 days and never the head.
  `attest_revocations` never purged. `attest_keys` never deleted. `attest_key_secrets` deleted at retire + 7 d and
  immediately at revoke. `attest_bundle_objects` is a cache (history trimmed to 60). `attest_push_jobs` 30 d.
* **Disclosure material** per statement: `gzip(PCJ-lines)` of `{"tree":..,"index":..,"nonce":hex,"record":{..}}` for
  every leaf of the three tree kinds, encrypted with the same wrap as signing seeds (kind `disclosure`, AAD
  `tenant|estate|publication|seq`). Kept for the last 7 statements per publication and any the owner pins
  (`POST /v1/attestations/{id}/pin`); a graph above 100 000 leaves is stored only when pinned. It contains node refs,
  so reading it is `admin`, audited, and never public.

### 5.10 Policy-set rules (what edits do to the commitment)

| Event | Effect |
|---|---|
| create custom invariant | new policy leaf; `total` and `enabled_custom` rise; not disclosed unless `disclose_custom` |
| enable std | a copy of the shipped definition; its digest must equal the shipped one |
| edit custom (PUT) | new digest, `version + 1`, a new `invariant_versions` row: the policy leaf and the result digest change and `versions` rises; a verifier holding the previous statement reports `digest.changed` |
| disable or archive (DELETE) | row kept, `enabled=false`: the leaf flips, the result disappears, the enabled counts fall, `total` stays; the verifier states "K declared invariants are disabled" |
| re-enable | no result until the next fresh evaluation says so (old stored verdicts are ignored) |
| a row is physically deleted (DB admin) | `total` or `versions` decreases: the verifier flags `policy.shrank` against the previous statement. A purge requires a new estate chain (a new estate id, `seq` restarts). Never silent. |
| engine upgrade changes a std digest | the registry lists the digest per ruleset; an old verifier reports `engine.ruleset_unknown` (UNVERIFIABLE) rather than accepting |

A flapping disable/enable between two statements is invisible at statement granularity; the anchored audit chain
records every toggle (`assurance_invariant_*` actions), so an auditor with chain access can check.

## 6. Publishing, public routes, bundle

### 6.1 Bundle layout (identical hosted and pushed; hosted prefix `/v1/public/attest/{domain}/`, self-hosted `/.well-known/paddock/`)

```
bundle.json                  {"spec":"paddock-attest-bundle/v1","domain":"example.com","generated_at":"<T>","head":{"seq":N,"digest":"sha256:.."},"paths":[...]}   (unsigned convenience)
keys.json                    3.2
revoked.json                 3.4 (DSSE)
attestation/latest.json      the DSSE envelope; byte-equal to attestation/<seq>.json (a mismatch is chain.latest_mismatch)
attestation/<seq>.json       immutable history (the last 60 are served; the full ledger stays server-side)
attestation/index.json       [{"seq","statement_digest","issued_at","valid_until","kid"}], capped at 60, unsigned convenience
anchors/latest.json  anchors/<max_id>.json  anchors/index.json       public anchor docs (3.7)
scope.json                   OPTIONAL, the scope document of 5.6 (owner choice)
proofs/<seq>/<tree>.json     RESERVED path for inclusion proofs; never served by the hosted routes
```

Static hosts used by browsers need `Access-Control-Allow-Origin: *`. `index.json` and `bundle.json` are conveniences:
the verifier never trusts them for a decision.

### 6.2 Eligibility and the `serving` flag

`serving = published AND scope proof verified AND binding verified AND the active key named in DNS AND not
suspended/held AND license ok AND a head statement exists`. It is materialised into `attest_bundle_objects.public` (all
objects of the publication, one transaction) by: publish and unpublish calls, issuance, the DNS recheck, key events,
and a **sweep every 5 minutes** (recomputed from scope proof, binding and key status; `scope_proof.reverify_due` has
no hook, so the sweep bounds the staleness to 5 minutes plus the cache max-age). Domain collision (two workspaces of
one org): the global partial unique index is the arbiter; a losing flip returns `409 domain_in_use` (generic), which
reveals existence only to a caller who already proved DNS control of that exact domain for their own key. DNS is the
tie-breaker: when the other estate's binding stops verifying its `serving` goes false and a retry succeeds.

### 6.3 Hosted public routes (`routers/public_attest.py`)

All `GET`/`HEAD`, unauthenticated, prefix `/v1/public/attest/{domain}`: `/` (bundle.json), `/keys.json`,
`/revoked.json`, `/attestation/latest.json`, `/attestation/index.json`, `/attestation/{seq}.json`,
`/anchors/latest.json`, `/anchors/index.json`, `/anchors/{max_id}.json`, `/scope.json`. Proofs are not served.

* Validate the path against a strict per-route allow-list regex; normalise the domain (ASCII LDH or punycode, lowercase,
  no trailing dot, at most 253). **Any** invalid, unknown, unpublished, not-serving, failing or foreign case returns the
  **same 404**: identical body `{"detail":"not found"}`, identical headers (including `Cache-Control: public,
  max-age=30`) and one indexed lookup in every case (no extra queries on the miss path), so there is no oracle in
  status, body or, practically, timing. No 400 or 422 variance.
* Lookup under `tenancy.auth_lookup()` (no tenant stamped), in one transaction `set_config('app.attest_lookup','on',true)`
  and `set_config('app.attest_domain', sha256(domain), true)`, then
  `SELECT body, content_type, etag, cache_control FROM attest_bundle_objects WHERE domain_key=$1 AND path=$2 AND public`.
  The only cross-tenant policy is `attest_public_lookup` (SELECT only, exact match, no `LIKE`, nothing enumerable). The
  route never reads live tenant tables.
* Headers: strong `ETag: "sha256-<hex>"` with `If-None-Match` giving 304; `Cache-Control`: `latest.json` `public,
  max-age=60`, `keys.json` `public, max-age=3600`, `revoked.json` `public, max-age=300`, `<seq>.json` and
  `anchors/<n>.json` `public, max-age=31536000, immutable`; `X-Content-Type-Options: nosniff`;
  `Access-Control-Allow-Origin: *` set in the handler (the global CORS middleware excludes `*`), no credentials;
  `Content-Type: application/json`. Object size cap 512 KiB (`keys.json` 64 KiB).
* Rate limiting: `auth.GovernanceMiddleware` already throttles anonymous public routes (`ANON_PUBLIC_PER_MIN`, 240 per
  client per minute, in process, no Redis dependency for static reads); add a cheap per-domain in-process bucket and
  rely on `Cache-Control`/CDN for scale. No audit row per public read (an amplifier); best-effort Redis counters for
  `reads_24h`.

### 6.4 Push targets (`attest/targets/`)

```python
class PublishTarget(Protocol):
    kind: str
    async def put(self, objects: Sequence[BundleObject], *, dry_run: bool = False) -> PushReceipt   # idempotent
    async def delete(self, paths: Sequence[str]) -> None
    async def read_back(self, paths) -> dict[str, bytes | None]                                       # drift check
```

* Ships now: **hosted** (implicit, the DB objects), **file** (atomic write of the bundle directory: the supported route
  to nginx, any static host, or a GitHub Pages checkout driven by the customer's CI), **s3** (boto3 `put_object` with
  `ContentType`, `CacheControl`, `ChecksumAlgorithm=SHA256`; ambient IAM role or a role ARN, never stored secrets; a
  custom `endpoint_url` passes `integrations.netsafety.validate_outbound_url`). Stubs: GitHub Pages API (token sealed
  with `integrations.secrets.encrypt_secrets`, never returned), R2.
* **Ordered writes**: `revoked.json`, `keys.json`, `anchors/*`, `attestation/<seq>.json`, `attestation/index.json`,
  `attestation/latest.json`, `bundle.json` last. A reader never sees `latest.json` before its signing key is listed, and
  a revocation is never delayed behind a slow history upload. After a push `read_back` compares sha256 of
  `latest.json` and `revoked.json`; drift sets `last_error` and a status warning.
* Jobs: `attest_push_jobs` with attempts, backoff (1 min to 1 h, max 12), dead-lettering. A push failure never blocks
  issuance or hosted serving. `POST /targets/{id}/test` does a dry-run read-back.

### 6.5 Privacy review before publishing

`GET /v1/attestations/preview?publication=` returns the statement exactly as it would be issued now (dry run, not stored,
not signed, `seq` tentative) so the owner can review it before `published=true`. The publish confirmation text states
what is visible (counts, coverage integers, sizes, engine version, the domain itself), that a `holds_only` reader cannot
tell violated from withheld, that the estate's domains are linkable through the key fingerprint, and that the
attestation is not a security assessment.

### 6.6 Proofs and disclosure

Inclusion proofs expose a leaf (node refs, IPs). They are produced only on request by an `admin`
(`GET /v1/attestations/{id}/disclosure?tree=&index=`), returned as the proof file of 2.3 for the owner to hand to an
auditor, and are never part of the public bundle. The reserved bundle path exists so a later release can publish owner
selected proofs without a format change.

### 7.2 RBAC

`auth.py` classifies safe methods as `read` and any unclassified mutation as the deny-closed `admin`, so the private
routes need no rule. Exactly two rules are added (owned by P3.6, kept additive because P2.1 also edits the file):
`_rule("GET HEAD", rf"/v1/public/attest/{_ANY}(/.*)?", None)` (public, next to the growth public rules) and
`_rule("GET", rf"/v1/attestations/{_ANY}/disclosure", "admin")` (otherwise a GET would default to `read`). A POST to
`/v1/public/attest/*` is denied. Mutations that change the outward claim (publish, unpublish, revoke, suspend, resume,
activate, retire, delete of a key, domain, publication or target) require `justification` (min 8 characters) recorded
in the audit row. Mutations are gated with `billing_gate.require_paid(...)`; reads and DELETEs are never gated (as in
P1).

### 8.2 Command line and report

```
paddock-verify [--policy F] [--max-age D] [--min-coverage P] [--require ID[:TIER]]... [--offline]
   [--dns-resolver SPEC]... [--dns-min-resolvers N] [--dns-record TXT] [--roots F] [--add-roots F] [--std-registry F]
   [--state-file F | --no-state] [--history required|if_available|off] [--history-depth N] [--anchor-file F]
   [--max-anchor-age D] [--proofs-dir D] [--keys F] [--revoked F] [--now T] [--allow-private] [--timeout S]
   [--json] [--quiet] [--no-color] [--explain CODE] [--print-roots] [--version]  TARGET
```

`TARGET` is a domain (`example.com`: DNS first for the `keys=` hint, else `https://example.com/.well-known/paddock/`),
`https://base/`, a **file** (a DSSE envelope; siblings or `--keys/--revoked` supply the rest) or a **dir** (the bundle
root or its parent containing `.well-known/paddock`). `--now`, `--dns-resolver file:`, `--state-file`, `--roots`,
`--std-registry`, `--anchor-file`, `--json`, `--offline` are the **normative conformance interface** every conforming
CLI exposes. Custom roots print "custom trust roots in use". All I/O sits behind `Fetcher` and `Resolver`, so
`verify(bundle, policy, now=, resolver=, state=)` is pure and embeddable.

**Exit codes**: `0` accepted, `1` rejected, `2` unverifiable, `64` usage or config error (argparse is patched so `2`
means only "unverifiable"). **Precedence: any reject gives 1, else any unverifiable gives 2, else 0.** Any unexpected
exception exits 2 with `internal.error`, never 0. Never print an accepted headline on partial evaluation.

`--json` report (`verifier-report.schema.json`): `{report_version, verifier{name,version}, spec:"1.0", now, target,
profile:"baseline"|"policy", policy_sha256, decision:"accepted"|"rejected"|"unverifiable", exit, primary, reasons[{code,
class, step, params, message}], warnings[], checks[{step, id, status:"pass"|"fail"|"unverifiable"|"skip"|"not_evaluated",
codes[]}], subject, key{kid, custody, vendor_certified, dns_bound, dnssec}, statement{seq, issued_at, valid_until,
snapshot_at, policy{total, enabled_std, enabled_custom, disclosed, disabled}, min_tier}, results[{invariant, verdict,
status, tier, coverage{covered, universe, percent_floor, required_bp}, valid_until, exceptions}], human[]}`. `params`
hold only schema-validated tokens, so attacker text never reaches the terminal.

**Fetch rules**: https only, no credentials, at most 3 redirects (https to https), 10 s timeout,
`Accept-Encoding: identity`, byte caps while streaming, an IP-literal host refused, resolved loopback/link-local/private
targets refused unless `--allow-private` (the connect-time TOCTOU is documented; embedders inject their own `Fetcher`).
Limits: envelope 512 KiB, payload 256 KiB, keys/revoked/policy/proof files 256 KiB, JSON depth 16, 8 MiB per run.

### 8.3 Check order (normative; the spec's `07-verification-procedure.md` is this list)

Notation: R reject (exit 1), U unverifiable (exit 2), W warning. **Abort rules**: a reject in steps 0 or 1 aborts
everything; an unsupported `predicateType` (U) continues with steps 2 and 3 only (so an authentic but too-new statement
reports U and a forged one reports R); a reject in steps 2 to 4 marks steps 5 to 10 `not_evaluated` (policy is never
judged on unauthentic data); steps 5 to 10 run to completion and collect **all** reasons in step order; the first
reason is `primary`.

| Step | Checks |
|---|---|
| **0 INPUT** | acquire files; size limits; strict JSON parse (duplicate keys, BOM, trailing bytes, NaN, bool-as-int, number rules, depth) |
| **1 SCHEMA** | envelope shape (three keys, one signature of two keys), exact `payloadType`, strict base64, ASCII, PCJ round trip, Statement shape (`_type`), exactly one subject with a valid name and the digest `sha256(name)`; `predicateType` known; **strict** predicate keys; every grammar of 1.3 (T, H, KID, ESTATE, INV, UINT); `seq`/`prev` coupling (`prev` iff `seq > 1`); `issued_at < valid_until <= issued_at + 7 d`; `snapshot.at <= issued_at <= snapshot.at + 900 s`; results sorted, unique, at most 256; verdict-specific fields exactly as 1.3; `HOLDS` has `tier` and `valid_until`; counts `disclosed == len(results)` and `disclosed <= enabled_std + enabled_custom <= total` |
| **2 SIGNATURE** | exactly one signature; `keyid` in `keys.json`; `predicate.kid == keyid`; Ed25519 pre-checks (2.5); verify over the PAE of the decoded payload |
| **3 TRUST** | `kid` equals the derivation from the cert's public key; cert chain (tenant cert signed by an issuer in `issuers`, whose cert is signed by a pinned root; payload equals the listed entry; `usage == attest`; every window contains `issued_at`; the key window also contains `valid_until`); `estate` in the cert equals `predicate.estate` equals the `paddock-estate` subject when applicable; **DNS binding** when the subject is `dns:` (4.3); subject domain equals the domain being checked |
| **4 REVOCATION** | `revoked.json` present, signed by a chained revoker or issuer, fresh (3.4); the key not revoked (`key_compromise` rejects regardless of `issued_at`; `superseded` rejects `issued_at >= revoked_at`); no issuer revoked (the root-signed list shipped with the release); `seq >= min_seq` of the subject |
| **5 TIME** | `now < valid_until` (end exclusive) else `time.expired`; `issued_at - 300 s <= now`; consumer `max_age` on **both** `issued_at` and `snapshot.at`; `anchor.at <= issued_at` |
| **6 CHAIN** | when history is available: `latest.json` byte-equal to `<seq>.json`; `prev` equals sha256 of the payload bytes of `<seq-1>`; previous seq is `seq - 1`; the local state high-water mark per subject (lower seq is `chain.seq_rollback`; same seq with a different digest is `chain.fork`); against the previous statement `total` and `versions` never decrease (`policy.shrank`), `anchor.max_id` never decreases, `digest.changed` is reported. No history: warning or UNVERIFIABLE per policy `history`. State is updated only after steps 0 to 4 pass |
| **7 DISCLOSURE AND ENGINE** | `limits.id` known and `limits.digest` equals the embedded text's sha256; `engine.name`; the `ruleset` known (else U) and every `std:` result digest equals the registry's for that ruleset; advisories for `engine.version`; **disclosure self-check**: `verdicts=all` and `custom=true` requires `disclosed == enabled_std + enabled_custom`; `verdicts=all` and `custom=false` requires the number of std results `== enabled_std`; whenever `custom` is false no result may have a non-`std:` id; the counts and the missing std ids (computed from the registry) are always reported |
| **8 RESULTS** | per result: `tier` in `{configured, observed}` (`tested` is INVALID in v1: no probe-evidence profile exists yet; `declared` is never valid on a HOLDS), `tier >= min_tier`, `tier <= cap(assertion)`; coverage `covered <= universe`, `estate_covered <= estate_universe`; a HOLDS needs `universe >= 1`, `covered * 10000 >= required_bp * universe` and `selected.to >= 1`; a HOLDS `valid_until > issued_at`; warning when `selected.stop_at * 2 > estate_universe`; the derived status (8.5) |
| **9 ACCEPTANCE POLICY** | for each `require` entry: present; HOLDS (VIOLATED, UNKNOWN or derived EXPIRED reject); tier at least `min_tier`; coverage at least the consumer threshold (**integer** cross-multiplication); optional pinned digest; exceptions at most `max_exceptions`; `stop_at` share; per-invariant `max_age` against `snapshot.at`; then **all** results: any VIOLATED that is not required is `invariant.unrequired_violation` (reject by default; `violations: warn` downgrades); policy `disclosure: complete`; `require_latest`; `std_registry: strict`; engine advisories |
| **10 OPTIONAL** | audit anchor (the bundle's `anchors/<max_id>.json` or `--anchor-file`): Ed25519 v2 signature by an estate `anchor` key valid at `at`, fields equal the statement's, `digest` equal, estate equal; a v1 HMAC anchor is `anchor.not_ed25519`; Merkle inclusion proofs when supplied |

### 8.5 Derived values and what each verdict means to a consumer

* `effective_status(result, t) = "EXPIRED"` iff `verdict == HOLDS` and `t >= result.valid_until`, else the verdict.
  `EXPIRED` is **derived, never stored, never issued**. A statement with `t >= valid_until` is `time.expired` as a
  whole.
* The statement-level tier printed is the minimum over the disclosed HOLDS tiers; there is no signed field for it.
  Percent shown is `floor(covered * 100 / universe)` so `41/42` never displays as 98 or 100.
* HOLDS (current): "no counterexample found under this evidence, coverage and freshness". HOLDS past its
  `valid_until`: EXPIRED, "says nothing about now", never a pass. VIOLATED: "a counterexample exists" (count only).
  UNKNOWN: "undetermined, not a pass" with the reason phrases. Absent: "not disclosed" with the counts.
* The verifier **never** turns UNKNOWN into HOLDS, never aggregates verdicts into a score, and never prints a bare
  green "pass" or "secure". Without a policy the headline is `VALID under baseline profile`; with a policy it is
  `ACCEPTED under policy <name>`, `REJECTED: <primary message>` or `UNVERIFIABLE: <primary message>`.

### 8.6 Acceptance policy (JSON normative, a strict YAML subset as sugar)

```json
{"policy_version":1,
 "require":[{"invariant":"std:no-internet-to-datastore","verdict":"HOLDS","min_tier":"observed","min_coverage":"0.95","max_age":"24h","digest":"sha256:.."}],
 "max_age":"48h","min_coverage":"0.95","disclosure":"any","violations":"reject","max_exceptions":null,"max_stop_at_share":null,
 "trust":{"vendor_cert":"required","dns_binding":"required","dnssec":"off","revocation":"required","revocation_max_age":"72h"},
 "history":"if_available","std_registry":"strict","engine_advisories":"reject","anchor":"off","require_latest":false}
```

Defaults shown are the **baseline profile** (no `--policy`): authentic, chained to a pinned root, bound by DNS (for
`dns:` subjects), not revoked, current, `max_age` 48 h, every disclosed HOLDS at least 95 % covered, no disclosed
violation, std digests pinned, and **nothing required of the content** (`require` empty, `disclosure: any`). The first
output line says `profile: baseline (no acceptance policy given; nothing requires specific invariants)` and the JSON
has `"profile":"baseline"`; exit 0 then means only "authentic, current, honestly typed, nothing disclosed is violated".
`disclosure: complete` requires `verdicts = all` and `disclosed == enabled_std + enabled_custom`. Only
`verdict: HOLDS` is allowed in `require`. Thresholds parse with `Decimal` (at most 4 decimals) into basis points. CLI
overrides: `--max-age`, `--min-coverage`, `--require ID[:tier]`. The report prints `policy_sha256` (sha256 of the PCJ
of the parsed policy).

**YAML subset ("PPY", about 200 lines, no PyYAML)**: comments, 2-space indentation (tabs are an error), block mappings
and sequences, sequence items that are flow mappings (`- { invariant: std:x, verdict: HOLDS }`), flow sequences
`[a, b]`, double-quoted strings (`\"` and `\\` only), integers, decimals (kept as `Decimal`), `true`/`false`, bare
strings matching `[A-Za-z0-9_.:/%+-]+`. Rejected with `config.policy_invalid` and a line number: anchors and aliases,
tags, block scalars, multi-document, merge keys, `yes/no/on/off/~/null` as scalars, duplicate keys, depth over 6, file
over 64 KiB, non-ASCII. `primitives/policy-parse.json` pins the accept/reject table and CI compares accepted cases with
PyYAML `safe_load` (dev-only). The MVP doc's example parses as is.

**Forbidden vocabulary** (case-insensitive whole words): `secure`, `secured`, `safe`, `safely`, `protected`, `compliant`,

### 8.8 Registry, advisories and limits files

* `std-registry.json` (written by `scripts/export_std_registry.py --check` from `paddock_assurance/stdlib/*.yaml` using
  the engine's own `digest()`, CI fails when a std YAML changes without a registry update):
  `{"registry_version":1,"rulesets":{"sha256:<ruleset>":{"engine":"0.3.0","std":{"std:no-internet-to-datastore":{"digest":"sha256:..","assertion":"unreachable","name":"No internet path reaches a data store","status":"current"}}}}}`.
  `ruleset = sha256(PCJ({"std":[{"digest":..,"id":..},...sorted by id],"v":1}))` over the shipped library. Names are the
  library titles (vetted against the forbidden vocabulary). Older rulesets stay with `status: deprecated` (accepted with
  a warning); `withdrawn` rejects. The registry is the **only** place a std digest becomes trusted; the verifier cannot
  recompute digests (it would need the DSL canonicaliser).
* `advisories.json`: `{"advisories_version":1,"items":[{"id":"PA-ADV-0001","engine":"0.2.0","effect":"reject"|"warn","summary":"<ascii>"}]}`.
  Empty at the first release; each engine release adds entries.
* `limits-v1.txt`: section 13.2. The verifier embeds the text for every known id and prints it (or a pointer) with every
  report; an unknown id or hash mismatch is INVALID.

### 8.9 Versioning

`predicateType` carries the major. A change to PCJ, the Merkle rules, the check order, a closed enum (a new tier, verdict
or direction) or the meaning of a field is a new major. Verifiers support the current and the previous major for at
least 24 months; publishers may dual-publish `latest.json` (v1) next to a later `latest-v2.json`. `std-registry`,
`advisories` and `trust_roots` versions are independent of the spec version. A security-relevant change to a normative
rule needs vectors and a CHANGELOG entry in the same commit. The verifier prints the spec version it implements; a
statement with a higher major exits 2. `log_inclusion` is **reserved**: no signed field in v1; a v2 predicate or an
unsigned bundle file `attestation/<seq>.inclusion.json` may carry a transparency-log entry later, because log entries
are created after signing.

## 9. Test vectors and conformance

### 9.1 Independence design: three implementations, one corpus

(a) `tools/gen_vectors.py` and `tools/gen_cases.py` are the source of truth: a **third, independent** stdlib +
`cryptography` implementation written from the spec text, importing nothing from `verifier/` or `orchestrator/` (an AST
test enforces it). (b) The verifier passes the corpus (`verifier/tests/test_conformance.py`). (c) The orchestrator
producer passes it (`orchestrator/tests/test_attest_vectors.py`): for each `producer: true` vector, feed
`inputs.engine_results` (real `Result.to_dict()` shape: floats, microsecond timestamps, parameterised reasons, null
tier), a fixed `now`, key seed, `seq`, `prev` and `commit_key` through the real builder and signer and require
**byte-identical** payload and envelope. (d) CI runs the generator with `--check` (regenerate to a temp dir and diff,
like `export_openapi.py --check`) plus `MANIFEST.json` (sha256 of every file and `spec_version`); changing a vector's
expectation requires a CHANGELOG line. A producer bug fails (c) instead of being baked in.

### 9.2 Determinism

No randomness and no clock. Keys are `Ed25519PrivateKey.from_private_bytes(sha256(b"paddock-conformance-seed/v1/" + name))`
for names `root-1`, `root-2`, `issuer-1`, `revoker-1`, `tenant-a`, `tenant-b`, `anchor-a`, `attacker`; Ed25519 is
deterministic so signatures are byte-reproducible. The reference clock is `2026-12-01T12:00:00Z`, `issued_at`
`09:00:00Z`, `valid_until` next day `09:00:00Z`, domain `example.com`. `commit_key` for vectors is 32 bytes of `0x01`.
Committed JSON uses sorted keys, 2-space indent and a trailing newline; signed bytes are carried as base64. The seeds are
public test keys: a release-pipeline test greps `trust_roots.json` and fails if a conformance key is present.

### 9.5 Conformance runner (`conformance/run.py`, stdlib only)

`run.py --impl "paddock-verify" [--filter tag] [--primitives-adapter module]`. For each case it materialises recipes into
a temp dir, runs `<impl> --json --offline --now <T> --roots <test-roots> --dns-resolver file:<dns.json> [--state-file ..]
[--policy ..] <target>`, and compares exit, decision, the **exact ordered code list**, warnings and primary, then scans
the output for forbidden terms. **Level A** (CLI, mandatory) covers every case. **Level B** (a primitives adapter) is
optional, but every primitive pin also has a Level A case that fails if the primitive disagrees (a wrong PAE can only
break a valid vector, a wrong base64 only the variants), so an implementation without an adapter cannot diverge
silently. The runner prints a conformance matrix and exits non-zero on any mismatch; an implementation may claim
conformance only against a named `spec_version` plus the MANIFEST hash.

### 9.6 Further verifier tests (owned by the verifier packages)

* **Mutation property**: for the compact valid bundle (envelope, keys.json, revoked.json) flip every bit (all bits for
  small files, a seeded sample of 3000 for large ones), truncate at every 7th byte, delete each key of the predicate:
  exit must never be 0. Any exit 0 is a spec bug or an unsigned-field leak. (Whitespace in unsigned outer JSON is
  excluded because the committed valid bundle is compact.)
* Strict JSON parser fuzz: duplicate keys at every depth, depth bomb, huge numbers, NaN, BOM, trailing bytes, lone
  surrogate escapes, invalid UTF-8; linear time on 512 KiB inputs; no `RecursionError`.
* Exit-code precedence combinations; DNS (`FakeResolver`: nxdomain, nodata, servfail, timeout, disagreement, quorum, AD;
  a DoH wire builder and parser against recorded responses including compression pointers, truncation and oversize);
  fetch safety on a mocked transport; the `codes.py` equals appendix A test; schema cross-check with `jsonschema`
  (dev-only) so the JSON Schemas and the code validators cannot drift; the independence lint of 8.1.

## 12. Non-goals and honest limits

### 12.1 What an attestation does and does not mean

* It means: *a named issuer's engine, running an invariant whose definition is identified by a digest, searched the
  evidence available to it at one time and found no counterexample; this much of the relevant estate had live evidence;
  the weakest evidence relied on was of this tier; the result is current until this time; the estate key that signed it
  is certified by Paddock's pinned root and named by the domain's own DNS.*
* It does **not** mean the organisation, its network or any system is secure, compliant, certified, insured or free
  of vulnerabilities; it is not a penetration test, an audit or a prediction; it says nothing about invariants not
  listed; it does not detect a compromised host that reports false data (agent facts are `configured`, never lifted by
  signature), malware, intrusions or misuse of valid credentials; the engine and its rules can have defects (hence
  advisories); identifiers are labels, not endorsements. These statements travel with every attestation as the pinned
  `limits` text (13.2).

### 12.2 Honest limits (each is documented in the spec's security considerations)

1. **Hosted custody**: a compromised orchestrator process (it holds the KEK in memory) or a DB dump plus the KEK can
   mint valid statements until the key is revoked. The merkle roots bind the issuer to a graph but do not prove it true.
   BYOK/KMS, an independently held anchor sink and a transparency log are the real mitigations and are later.
   The self-verify step catches bugs, not malice. The cert's `custody` and the verifier output say which applies.
2. **The offline replay window cannot be closed**: a copy of a statement that said HOLDS stays acceptable until its
   `valid_until` even after the estate flips. Mitigations: 24 h default life, immediate re-issue and supersession on a
   flip, `require_latest`, the revocation list's `min_seq`.
3. **`holds_only` is lossy by design**: a reader cannot tell violated from unknown from withheld; only the counts and
   the limits text say so. A tenant can also stop publishing. This is the owner's privacy-first choice (O3).
4. **The audit anchor is not a public proof of the chain**: the chain is keyed HMAC. Outsiders verify the signature,
   estate binding, monotonicity and (with an independent sink copy) byte equality; not chain contents.
5. **DNS binding**: no local DNSSEC validation in a stdlib verifier; AD is the resolver's claim; a registrar or DNS
   compromise defeats the domain anchor (the vendor cert is the second anchor); the resolver sees which domain is
   verified. A missed TXT update before key activation, or removing the old record too early, makes verifiers reject.
6. **No transparency log in v1**: a compromised key can backdate `issued_at` within its certificate window, so revocation
   for `key_compromise` invalidates every statement of that key (legitimate old statements become unverifiable after an
   incident). `log_inclusion` is reserved (8.9).
7. **Revocation latency** is bounded by the list's age; issuer or root revocation between verifier releases relies on
   the embedded lists (an online root-signed issuer list is deferred); old verifiers do not trust a new root.
8. **Privacy residue**: sizes, `covered/universe`, `estate_*`, the number of results, `seq` cadence, root-change timing,
   the engine version and the domain itself are visible; the linkage of an estate's domains through the key
   fingerprint is accepted (D31). Dropping `graph.size` or rounding counts is a later option.
9. **Evidence is not truth**: coverage counts assets with evidence, not the true estate; the unknown-edge soundness rule
   applies regardless of the floor, so a HOLDS can coexist with blind assets (limits item 3).
10. **A HOLDS can lapse daily** purely because of the operator's scan cadence (`max_age`), and consumers will see
    EXPIRED or UNKNOWN: `status` surfaces `lapses_at` and `limiting_invariants` and the docs recommend a scan cadence of
    at most `max_age/2`.
11. **Engine drift**: an engine upgrade changes std digests and the ruleset; old verifiers answer exit 2 until the
    registry is updated (the verifier warns when its registry is older than the statement's ruleset). A new engine
    reason maps to `other` until the enum grows.
12. **KMS limits are unverified**: Ed25519 availability and the raw-message cap (AWS: 4096 bytes) of KMS products; a
    nine-invariant statement is about 5 KB. BYOK therefore needs a digest-signing algorithm (P-256) and spec 1.1
    vectors; P3 ships the interface and the size check only.
13. **Interop is unproven**: Ed25519 raw keys, a custom predicate and exactly-one-signature DSSE have **not** been
    tried against `cosign verify-blob-attestation`; the MVP doc's claim is not promised until tested. The PCJ and
    base64 rules are stricter than DSSE/in-toto norms by design.
14. **Time**: the verifier trusts its host clock; `--now` exists for tests and audits; the state file reduces rollback
    acceptance but does not fix clock manipulation.
15. **Legal**: Apache-2.0 for a directory inside an AGPL repository and the "verified by" wording are legal-review items
    (READINESS CLA review is open); nothing is published to PyPI or announced before sign-off.
16. **Coupling**: the issuer depends on the runner's private helpers (5.2), on the library's `compile_text`/`Plan`/`Result`
    surface and on the graph document shape. P2.1 is changing `compile.py`, `model.py`, `parse.py` and `evaluate.py`
    right now (the working tree already shows engine `0.4.0`, with std digests unchanged at the time of writing). A P2.1
    change to any of these changes roots or breaks the adapter; the adapter's pin tests and the std-registry `--check`
    make the failure loud, and P3.5 re-reads the library surface before it starts.
17. **Cost**: a fresh evaluation per refresh adds evaluation load (per-estate lease, runner budgets, worker threads);
    above the leaf cap nothing is attested.

### 12.3 Explicit non-goals of P3

No UI (P6); no public "paste a domain" page (P6, the TS verifier is P6 with an optional spike here); no BYOK route, KMS
backend or HSM (interface and stub only); no transparency log or `log_inclusion` field; no multi-signature statements;
no `tested` tier in statements (P5); no per-invariant publish allow-list (modes only); no public serving of Merkle
proofs; no per-publication keys; no X.509; no online root revocation channel; no automatic closing of anything from an
attestation; no changes to the evaluation library, the runner, the builders, the agent or the dashboard; no TS or Go
verifier beyond the optional spike; no cosign interoperability claim.
